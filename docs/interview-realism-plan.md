# 面试流程向真实一面靠拢：第二轮方案（2026-09-13）

上一轮（docs/interview-phases-plan.md）把面试改成了"阶段 × 方法 × 预算"。用户跑了一场（会话 `cmu01v57s…`，字节豆包 Agent 开发 JD，标准节奏，全程短答/"不知道"）后指出：项目广度不够；基础题脱离 JD；连续答不上也不结束；基础题应与 JD 高度相关、尽量与项目有关。本文先看这场的原始记录，再对照 2026 年公开的一面实录，找结构性原因，给方案。**未经用户放行不改代码。**

## 0. 这场到底发生了什么

| 回合 | 阶段 | 面试官 | 候选人 | 系统判断 |
|---|---|---|---|---|
| 0 | 开场 | 请自我介绍 | "我做个 multiagent 项目也做过 agent harness" | 没接住这句话 |
| 1–3 | 项目 p1 | "为什么把对话原文、滚动摘要、常驻记忆、可检索记忆分开存，而不是直接塞上下文" → 追一层 | "因为会上下文爆炸" / "就是压缩，总结，检索" | thin ×2 → 关线程 |
| 3–6 | 项目 p2 | "为什么单独设计结构化 action 协议" → 追一层 → 提示 | "防止弱模型乱输出" / "我不知道" / "失败重试" | thin → 关线程。项目阶段 5 回合结束（预算 8） |
| 6–16 | 基础 q1–q11 | 线程池 / JMM 标志位 / synchronized HashMap / 缓存命中率 / 财报 PDF / 虚拟线程 / 客服 30 轮遗忘 / 评测集 / JSON 解析率 / LoRA 还是 RAG / P99 首 token | 11 次"不知道"（含 "buzhidao"、"别问了"） | 每题 failed → 下一题，直到累计预算到 16 |
| 17–19 | 场景 s1 | 评估体系升级 → 提示 | "不知道" ×2 | 结束。收尾话："没关系，我们换一道。今天的面试到这里" |

题池 14 道：backend-java 6 道（线程池、JMM、锁、虚拟线程、集合源码）、backend 2 道（缓存、幂等）、ai-llm 6 道。选包结果 `["ai-llm","backend","backend-java","project-deep-dive"]`。

### 直接原因（代码层）

1. **backend-java 被 JD 一句"熟练掌握 Python/Java/Go 等至少一门语言"拉进来**（`selector.packsForTopics`：任一命中的栈包就带上，连同父包 backend）。Agent 岗的题池里因此混进 8 道后端题。
2. **题池是从三个包的并集里按权重抽**（`topics.sampleTopics`）：ai-llm 12 个主题 vs backend + backend-java 25 个主题，领域包只加 1 分，栈包仍占半壁。没有"配额"概念。
3. **简历命中是减分项**（`topicWeight` 的 `-0.5·resume·(1-jd)`）。上一轮为了"技术题别撞项目"这样设计，方向与用户现在要的相反。
4. **项目阶段只有两个切入点，每个都是从简历某一行抠出来的"为什么 X 而不是 Y"**（`brief-agent` 要求"从具体场景切入、能让背过但不懂的人答错"）。候选人还没讲过项目，就被问设计取舍；答薄两次线程关闭，项目阶段就没题了。8 个回合的预算只用了 5，剩的顺延给了基础题，基础题反而问了 11 道。
5. **基础阶段没有"连败"规则**：`budget` 只按累计回合数走，答不上就下一题，直到预算耗尽。真实面试官三四道连续答不上会换方向、降难度或直接收。
6. **"别问了"不在结束意图的正则里**（`actions.INTENT_PATTERNS` 的 end 只有"结束/到此为止/不想继续/先到这/今天就到这"）。
7. **场景题与题池撞题**：s1 "评估体系升级"与 q8 "评估体系建设"同一件事。备课时场景题与题池互不知道。
8. **卡住后直接收尾的话术拼接错误**：`stuck` 任务的"一句话放下这题"模板 + `close_interview` 的收尾句拼成了"我们换一道。今天的面试到这里"。
9. 自我介绍只有一句话时，面试官既不追"展开说说"，也没用它挑第一个项目。

### 1.2 后端（Java）岗

bilibili 2026 年的 Java 一面实录标题一致是"拷打基础为主""基础加项目"；阿里云开发者社区的 2026 面试官自述则说"我们不问 HashMap 的扩容机制，不问线程池的参数……八股从'通过条件'变成了'不扣分条件'"，只问三个项目题：**最有挑战的功能是什么 / 遇到过什么坑怎么解决 / 重做会改哪里**。两者都成立：Java 岗仍问八股，但区分度在项目。

### 1.3 可以确认的规律

1. **基础题就是岗位领域的原理题**。Agent 岗问 RAG/LoRA/MCP/记忆/评估，外加候选人自己那门语言的 1–3 道基础（GIL、HashMap）；不会给 Agent 岗问线程池参数、缓存击穿。
2. **基础题多从项目里长出来**："你项目里 X 是怎么做的 → 还有什么方案 → 各自优缺点 / 原理"。项目和八股不是两个互不相干的清单。
3. **项目部分有固定弧线**：背景/为什么做 → 架构与核心模块 → 你负责的部分与实现细节 → 最难的问题怎么解决 → 效果/预期/指标 → 重做会改什么。一面通常深挖一个项目 20–30 分钟，第二个只碰一下。
4. **追问不深不浅**：每个回答追一层"就这些？为什么？还有别的方案吗？"，答薄就换角度，不在一个点上耗。校招不考名词定义，但会考原理（attention、LoRA 为什么省显存）。
5. **答不上就下一题，不提示**；连续答不上，面试官换方向或收短，整场不会因为答不上而无限延长。
6. 大部分一面有手撕（本项目已决定不做沙盒，这里不碰）。

## 2. 结构诊断：现在的模型差在哪

上一轮解决了"所有题一种方法、清单问完就完"。这一轮的三个现象各自对应一个仍然没对的结构：

| 现象 | 结构原因 | 不是这个 |
|---|---|---|
| 项目广度不够 | 项目阶段的单位是"简历某一行的切入点"，不是"这个项目的弧线"。切入点只有 2 个，答薄就没了 | 不是预算不够（8 回合只用了 5） |
| 基础题脱离 JD | 题池 = 从"命中的所有包"里按权重抽；包的选择靠关键词命中，没有"这个岗位的领域是什么、栈是什么"的判断；主题权重把简历命中当减分 | 不是模型写题写歪了（主题是代码定的） |
| 连续不会也不结束 | 基础阶段只有"回合数"一个终止条件，没有"候选人状态"的终止条件 | 不是预算太大 |

## 3. 方案

组织单位不变（阶段 × 方法 × 预算），改三件事：项目阶段的单位改成"弧线角度"，题池改成"配额 + 项目牵引"，各阶段加"候选人状态"的退出条件。

### 3.1 备课（brief v7）

**档位**：从 JD（"2027 届""应届""实习"）或简历（在读、预计毕业）判断 `level: campus | experienced`，写进简报。校招：基础题问原理与小场景，项目不要求线上规模；社招：基础题问排查与取舍。技能包里"校招侧重 / 社招侧重"两句现成，只是没喂给模型。

**项目**：不再是"切入点"，而是"项目 × 角度"。主项目（与 JD 最相关的）给完整弧线，第二个项目只给两段：

| 角度 | 主项目 | 第二项目 | 问法 | 带什么 |
|---|---|---|---|---|
| overview 背景与架构 | ✓ | ✓ | "先整体讲讲：解决什么问题、架构长什么样、你负责哪块" | 要在他讲的时候核对的简历假设 |
| module 你负责的模块深挖 | ✓ | ✓（一个点） | 从 overview 里他自己说的模块挑一个，追实现细节 | 简历上写了数字/机制的那几行做 leads |
| hardest 最难的问题 | ✓ | — | "做的过程中最难/花时间最久的问题是什么，怎么定位的" | 危险信号：只有"改了个配置" |
| outcome 效果与预期 | ✓ | — | "达到预期了吗、预期是什么、怎么量的、短板在哪" | 简历上的数字在这里验 |
| redo 取舍与重做 | ✓ | — | "重做会改哪里、当时为什么没这么做" | — |

每个角度是简报里一个 `project` 领域（`areaId` 如 `p1.overview`），同一 projectId。面试中一个角度一个线程：答得实就追（module 最多 3 层，其余 2 层），答薄或答不上就关这个角度、开下一个角度——**广度由角度保证，深度由回答决定**。简历只有一个项目时，主项目 5 个角度全给；没有项目时跳过。这个改法几乎不动 reducer：现有"关线程 → 开下一题"的机制照用，只是项目阶段的"题"从 2 个变成 5 + 2 个。

自我介绍：面试官的第一道项目题固定是主项目的 overview；模型可以在话里承接自我介绍提到的东西（"你刚说做过 harness，先整体讲讲这个助手"）。自我介绍只有一句话时不追，直接进项目（真实面试也这样）。

**基础题池**：三处改。

1. **选包**（`selector.packsForTopics`）：领域包 = 岗位名 + JD 得分最高的 domain 包（不变）。栈包的规则改为：JD 或岗位名**明确要求**一门栈（"Java 开发""熟悉 Spring"）时用它；JD 只是罗列"Python/Java/Go 至少一门"或不提时，用**简历的主语言**对应的栈包（本例 backend-python）；领域包不是 backend 时，栈包不再带父包 backend。cs-fundamentals 作为基础层始终可抽（OS / 网络 / 数据结构各 1 道的来源）。
2. **配额**（`topics.sampleTopics`）：题池按包分配名额，不再从并集里抽。标准节奏题池 12：领域包 8、栈包 2、cs-fundamentals 2。领域包主题不够时名额顺延。
3. **权重**（`topics.topicWeight`）：简历命中改为**加分**（+0.5·resume），JD 命中加分不变，最近问过的降权不变。备课提示词加一条：简历上碰过的主题，题要写成"从他项目里用到的 X 出发问原理 / 替代方案 / 边界"（ai-llm 包的"项目结合钩子"段现成，现在没喂给模型），并与该项目的 module 角度避开同一个实现细节（module 问"你怎么做的"，基础题问"这东西一般怎么工作、还有什么做法"）。

**场景题**：先于题池确定；场景题绑定的能力对应的主题从题池里排除（本例：场景题拿了"评估体系"，题池就不再抽"评估体系建设"）。

### 3.2 面试中

**项目阶段**：预算标准节奏 8 → 10（主项目 5 角度 + 第二项目 2 角度，弧线走完约 10–12 回合，与"一面 20–30 分钟深挖项目"一致），基础 7 → 6，场景 3 不变，总 20。角度按简报顺序开，但模型可以按候选人 overview 里提到的模块改写 module 角度的问题（`questionForArea` 的覆盖率门槛对 module 角度放开为"必须提到候选人说过的一个模块名"）。thin 的处理从"第二次 thin 关项目"改为"关这个角度、开下一个角度"；hint 每个角度一次。

**基础阶段加退出条件**（代码持有，进 `budget`）：

- 连续 3 题 `failed`（不会 / 跳过）→ 强制换方向：下一题必须来自不同的包或不同主题族，且优先题池里带"简历命中"的（他做过的东西更可能答上）。
- 连续 5 题 `failed` → 基础阶段结束，进场景题。
- 场景题也 failed 且已给过提示 → 直接收尾。整场最短路径：开场 1 + 项目若干 + 基础 5 + 场景 2。

**结束意图**：`end` 正则加"别问了 / 不想答了 / 算了 / 不面了"。

**过渡句**：换阶段时由代码在面试官的话前面加固定过渡（"项目先聊到这，问几个基础的。" / "最后一道场景题。"），不再靠提示词。第二项目开始时加"再聊聊另一个项目"。

**收尾话术**：stuck 后紧接 close_interview 的话改成"这题先放下。今天就到这里，稍后看报告"，不再拼"换一道"。

### 3.3 体验

- 房间阶段条：项目阶段显示"项目 · 主项目名 3/5 角度"。
- 报告"这场问了什么"：项目按角度列出（覆盖了哪几段、各段 verdict），一眼看出广度。
- trace：每回合标角度。

### 3.4 不做

- 手撕 / 口述算法：沙盒方案已搁置（memory: career-agent-skip-sandbox）。
- 交叉面 / 二面的复问：不在这一轮。
- 不引入"面试官人格"之类的随机性；差异来自题池抽样与候选人的回答。

## 4. 需要用户定的点

按用户要求，拿不准的不自作主张。每条给我的建议，用户改哪条说哪条。

1. **项目分配**：主项目走完整 5 角度、第二项目只 2 角度（建议，与面经一致）；还是两个项目各走 3–4 角度？
2. **基础题与项目的关系**：简历命中改加分、题写成"从你项目里的 X 出发"（建议）。这意味着基础题会和项目阶段的 module 角度讲同一个东西的两个面（怎么做的 vs 一般原理/替代方案）。接受这种重叠吗？
3. **连败阈值**：连续 3 题换方向、5 题结束基础阶段、场景题也失败就收尾（建议）。要不要更宽或更严？
4. **档位**：从 JD/简历自动判断校招/社招并影响出题风格（建议做，成本低）；还是先不分？
5. **栈包**：JD 罗列多门语言时按简历主语言给 2 道语言基础题（建议，字节面经里有 GIL/HashMap 这类）；还是 Agent 岗不问语言基础？
6. **预算**：标准节奏 1 + 10 + 6 + 3（建议）；还是保持 1 + 8 + 7 + 3？

## 5. 实施顺序（放行后）

1. `skills/selector.ts` 栈包规则 + `skills/topics.ts` 配额抽样与权重翻转（含测试）。
2. `interviewer/brief.ts` v7：`level`、项目角度（schema、`padProjectAreas` 改为按角度补齐）、场景题主题排除；`brief-agent.ts` brief-v12 提示词（角度、档位、项目结合钩子）。
3. `budget.ts` 连败退出条件；`reducer.ts` thin 在项目阶段的处理、过渡句前缀、收尾话术；`actions.ts` 结束意图。
4. `prompt.ts` interviewer-v9：项目阶段方法改为"按角度"，删过渡句指令。
5. UI：阶段条、报告按角度、trace。
6. 单测 + 真机一场（同一 JD，正常作答一遍、短答一遍）；文档 flow-before / flow-during 原地更新；删掉被替代的常量与分支。

## 8. 第三轮：广度保底、追问要有理由（2026-09-13，待放行）

用户又跑了一场（会话 `cmu085vc7…`，字节抖音 Agent 研发 JD，标准节奏，回答完整、逐题 86–95 分）后指出：只问了一个项目；过于追求深度、很多题方向类似；答得完善且 JD 不看重的不必深挖。

### 8.1 这场发生了什么

| 回合 | 线程 | 追问 | 内容 |
|---|---|---|---|
| 1–4 | p1-overview | 2（到上限） | 架构 → 记忆怎么拼进上下文 → 你负责哪层 |
| 4–8 | p1-module | 3（到上限） | 分层记忆 → 拼装顺序 → 滚动摘要触发 → 覆盖丢失 |
| 8–11 | p1-hardest | 2（到上限） | 压缩后重复执行 → 怎么确认是摘要 → 对照变量 |
| 11–17 | q1 q2 q3 | 各 1（到上限） | 召回归因、TTFT、微调复用 |
| 17–19 | s1 | 1 | 研发质量 Agent 工作流 |

项目预算 10 回合被三个角度吃光：outcome、redo、第二个项目一个都没开；三个角度追的全是记忆 / 摘要一件事（overview 的追问提前挖了 module 要挖的模块，hardest 的故障也在摘要上）。基础题 6 回合只问了 3 道，每道都追到上限。题池 8 道全是 ai-llm，栈包与基础包的主题模型第二次没写。

### 8.2 结构原因

1. **追问只有上限，没有"该不该追"**：回答完整时模型仍追到顶，因为规则只说"有实质内容就继续追"。真实面试官追问是有理由的——要验证一条线索或数字、回答含糊、或这是 JD 的核心能力；答得完整又不是重点，就一句"好"往下走。
2. **预算只给阶段，不为必问的题留位**：一个角度可以把整个阶段的回合吃光。上一轮"主项目约七成"只是提示词里的一句话，模型没照做。
3. **角度之间没有"换方面"的约束**：模型顺着候选人最能讲的东西一路追，三个角度问同一个模块。
4. **题池角色的题模型不写**：提示词说"也要写"，模型两场都跳过。

### 8.3 方案（宏观调控，不加"至少 / 至多"）

用户不要"至少 N 道、至多 N 层"这类硬编码，要宏观调控。宏观的杠杆只有三个：**阶段预算**（已有，唯一的硬数字）、**给模型的目标**（这个阶段结束时要覆盖什么）、**全局视野**（还剩多少回合、还没碰什么、追一次的代价）。数量怎么分配交给模型。

**A. 把取舍摆在模型面前（提示词）**
- 每回合的进度行改成"这个阶段还剩 N 回合；还没碰的：outcome、redo、第二个项目背景架构"——追一次就少覆盖一项，模型自己算。
- 阶段目标写明：项目阶段结束时应覆盖主项目的弧线和第二个项目的概况；基础阶段应覆盖不同方向（领域几道、候选人语言或计算机基础一道），题池里哪道与场景题撞了就不问。
- 追问规则从"有实质内容就继续追"改成"有理由才追"：verify（验证简历线索 / 数字 / 假设）、vague（含糊或只有关键词）、core（JD 核心能力，往深问）；答得完整又不是重点，一句"好"换角度 / 换题。
- 换角度换方面：每个角度落在还没聊过的模块；overview 的追问不提前挖 module 的模块；hardest / outcome 优先落在没聊过的部分。

**B. 追问自报理由（`probe.reason`，模型自报，代码不校验真假）**：进决策记录与 trace，看得见每次追问为什么追。这不是限制，是让决定可解释；连败、锚点也是这么做的。

**C. 题池的构成由代码定，问哪道由模型定**：抽样的角色配额（领域大头、栈与基础各 1/6）本身就是宏观分配；抽中的主题全部进题池（模型没写的用包里的好题，回到 v11 的做法），不再让模型在备课时决定写不写——备课模型两场都把栈与基础的题删了，"问不问"应该在面试中看情况定，不是备课时定。与场景题撞题在面试中由模型看着题池避开。

**D. 不动的**：阶段预算 1 + 10 + 6 + 3；每条线程的追问上限（module 3 / 其余 2 / 基础 1 / 场景 3，已批准的深度上限，先留着当安全网，宏观调控见效后可以再讨论去掉）；连败退出。

**E. 体验**：报告"这场问了什么"按项目分组、项目题只显示角度名；阶段条在项目阶段显示当前角度；兜底题目截到第一问（"你怀疑哪些差异、怎么快速定位、最终怎么……"这种一句三问的也要截）。

### 8.4 验证

同一 JD、完整作答再跑一场看：第二个项目有没有问到、追问的理由分布、基础阶段问了几道几个方向。如果模型拿着全局视野仍然一路追到底，再谈别的杠杆，不先加数字。
