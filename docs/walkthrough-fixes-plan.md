## D. 评分器压高分（需要决定）

证据：InterviewBench S5 上 DeepSeek 把 20 个高水平回答判成 14 个中等（加权 κ 0.51），gpt-5.4-mini 判对 10 个（κ 0.82）；本项目评分器蜕变测试里 28 个由更强模型写的"原版好回答"中位 86 分、只有 2 个到 90 以上。两处方向一致：DeepSeek 当评分者时顶部压缩。这是模型特性，不是提示词写错。

三条路，只选一条：

1. **评分 agent 换 gpt-5.4-mini**：bench 上定层级最准；每段评分成本约 2 倍（$0.0026 vs $0.0013，一场标准面试多花约 $0.01）；其他 agent 不动。
2. **提示词加顶部锚点**：在分带里写清 90+ 长什么样并给一个例子；便宜，但 bench 显示这是模型本身的偏向，效果存疑，要用 S5 重跑验证。
3. **不改分、改口径**：报告里等级用分带（优 / 良 / 中 / 差）而不是分数，把压缩藏起来。治标。

我的建议是 1，理由是唯一有外部证据支持的选项，且评分 agent 本来就与面试官分离、换模型不影响其他部件；换完用 `npm run eval -- scorer --k 1`（约 $0.6）和 bench S5 各验一遍。
