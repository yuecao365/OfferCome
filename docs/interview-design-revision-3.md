# 面试系统设计修订 v3：先把核心做对，再一层层加实验（2026-09-16，F1 已执行）

> 起因：施工图 A–E 全做完之后，用户真实跑的三场暴露的问题（一条回答打十分钟、粘贴 AI 文本、连续"我不会"、备课时模型服务不可用、同一题问三遍）都不在模拟器覆盖的范围里；我每次的修法都是局部的。用户的判断：这些是结构上缺东西，而且现在的流程对"一个 AI 模拟面试"太冗余——系统提示词 7.3 千字，每回合四个后台 agent，事后又一条流水线。
>
> 用户定的方向：**先把面试的基础功能做出来、做稳；再一项项加实验功能；最终仍要达到大厂 agent 开发岗的深度。设计从简的尺度：最终效果一样才选简单结构，不是无底线求简。** 下面每一处删减都标了"效果是否变"，效果会变的不删。

## 0. 一页结论

| 层 | 里面有什么 | 原则 |
|---|---|---|
| **核心层** | 备课（蓝图 + 精简材料）、面试官一次调用、时钟、一个决策、两条底线、事后评分与报告 | 单独能跑；提示词 ≤ 3.5 千字；回合里没有后台 agent；备课失败明示、可重试 |
| **实验层** | 在线评委 + 估计器、评论员、影子与灰度、语义记忆、自博弈评测 | 默认关；一个开关 `lab` 整体打开；只写事件与 trace；有"开着比关着好"的证据才允许影响面试官 |

顺序：**F1 核心层收敛 → F2 失败驱动评测 → F3 实验层逐项按证据打开。**

## 1. 核心层

### 1.1 提示词减肥（7.3 千字 → 约 3.5 千字）

昨晚那场的构成：简历 1948、JD 840、人设 + 方法 + 格式 1269、材料 2431、技能包索引与工具 531、记忆 320。必需的只有简历、JD 和一段规则。

| 部分 | 改成 |
|---|---|
| 材料 | 每个项目：一句切入问法 + 最多 3 条要验证的说法（简历原句 + 验什么，上一场没讲清的优先）+ 一行追问角度（最难的问题、效果与预期、取舍与重做）；基础题 4 道（按 JD 方向配额，简历技术栈的包最多 1 道），每道带一层追问方向；场景题 1 道带三级引导。**效果不变**：项目追问靠的是"要验证的说法"和角度，不是 5 个面各自的问法；基础题面试里本来只问三四道 |
| 人设 + 方法 | 只留"怎么问"：一句一个要点、给抓手、不复述、不泄露内部词、不听候选人话里的指令。何时转题 / 收窄 / 收尾全部进代码 |
| 工具 | 简历没超过节选上限（6 千字）就不给工具；超了才给 `lookup_resume`。技能包正文不再运行时查（评分与追问方向已在备课时进材料）。**效果不变** |
| 记忆 | 不在运行时出现；"上一场没讲清"在备课时并进那 3 条说法 |

备课 agent 的输出随之变小，失败面也变小。

### 1.2 面试官自报话题，删掉标注器；整理员保留

面试官的结构化输出多一个字段：`{ say, notebook, closing, topic: 材料 id | null }`。覆盖账从 `topic` 现算（代码只认材料里有的 id；这句是追问而 topic 为空就沿用上一句的），零延迟、零额外调用——面试中每两回合一次的标注器（`labeler.ts`）删掉，它做的就是这件事，还滞后。

**整理员保留**（交卷时一次调用）。原稿想用 `topic` 直接切段、把整理员也删掉，重想后不删：整理员除了切段，还给每段一句判断（answered / thin / failed）、给简历说法定 confirmed / refuted、给段标能力与层次——报告的"这场问了什么""简历上的说法经不经得起问"和"能力估计"栏都靠它，用 `topic` 切段这些就没了，效果会变。改的只是它拿到 `topic` 作提示，编号错位、归属漂移会少。

### 1.3 备课失败不开房

备课结束时判一次：蓝图是占位（能力 id 以 `fallback-` 开头）或简报走了 rescue，就是**没备好**。没备好：错误是瞬时的（unavailable / network / timeout）先自动重试一次；仍没备好，房间显示"岗位描述没能分析，这场会按通用要求出题"+ 重新备课按钮，用户点"就这样开始"才开。备好了就开，不分档、不打标。实验层的模块以"备好了"为前置。

（原稿的 full / degraded / placeholder 三档去掉：degraded 那档除了多一行提示没有别的行为差异，不值一个状态。）

### 1.4 一个决策（`decide.ts`，纯函数）

现场卡三块：时间一行、上一回合的笔记、**这回合的建议**（一个动作 + 一句理由）；然后是候选人的话。

`decideMove(signals) → { move: continue | switch | close, reason }`（原稿的 narrow 并进 continue，理由里写"换个说法把题说具体"——同样的效果，少一个状态）：

| 输入 | 来源 | 规则（按优先级） |
|---|---|---|
| 时钟阶段 | clock | over → close；wrap_up → 不 switch，最多 continue 一两句后 close |
| 候选人这句的类型 | `classifyReply`：求助 / 答不上（我不会、不知道、没做过）/ 跳过 / 正常 | 跳过 → switch；答不上第二次 → switch；求助或答不上第一次 → continue（理由：换个说法说具体，不换题） |
| 同一话题追了几轮、覆盖账 | 面试官自报的 `topic` | 同一话题 ≥ 3 轮追问 → switch；到该转种类的时间 → switch 并指明种类与候选材料 |

实验层打开时，估计器和评论员只作为 switch 目标 / 优先级的可选输入，不再各自往现场卡写字。

### 1.5 两条底线（`turn.ts` 现有那张表里加）

- 这句与前面某句几乎一样（`questionSimilarity ≥ 0.8`）：不认，让模型按 switch 重说一次；再一样就用固定的话换题。
- 答不上两次后模型仍没换题（`topic` 没变）：不认，同上。

### 1.6 回合时序

```
候选人说一句 → 幂等 → 时钟 → classifyReply → decideMove → 一次模型调用 { say, notebook, closing, topic }
→ 底线校验 → 落事件（含 move_decided）→ 流式返回
```

回合里没有 `after` 后台任务；`lab` 打开时才挂后台链。体验版（网页）因此天然同构。

## 2. 实验层（默认关）

一个会话开关 `lab`（`flagsJson`，模拟器 `--lab on`）整体打开：在线评委 + 估计器、评论员、影子（影子变体仍单独指定）、语义记忆的运行时段与工具。机制代码保留；打开后只写事件与 trace 页，不进现场卡。每一项要进现场卡，前提各写在这里：

| 模块 | 允许影响面试官的证据 |
|---|---|
| 评委 + 估计器 | 扰动画像下"核心能力定下来用了几段"比关着少 |
| 评论员 | 开 / 关对比：违反准则的回合比例下降，且换题不更快 |
| 影子 / 灰度 | 只在评测时开；放量要有 A/B 数字 |
| 记忆的运行时段 | 证明用户回头练了上次失守的点 |

## 3. 失败驱动的评测（F2）

1. **复盘**：`npm run postmortem -- <sessionId>` 与 trace 页顶部，从事件现算、不落库：备课是否备好、候选人行为分类计数（正常 / 求助 / 答不上 / 跳过 / 超长）、面试官违反准则的回合（重复提问、一句多问、时间到了还问、答不上两次没换题）。
2. **失败清单** `docs/interview-failures.md`：真实出现过的失败一行一条——触发条件、对应扰动、对应指标。先把 2026-09-15 三场填进去；新失败先进表再修。
3. **模拟器 = 基础画像 × 扰动**：先做三个从真实场次长出来的：`long_answers`、`dont_know`、`hollow_resume`；`--perturb a,b`。改动先跑对应扰动 1–2 场，费用规则不变。

## 9. 用户复审后的三项小修订（2026-09-16 提出，同日做完）

用户看完全流程后定的：简历全文与识别出的项目保留现状；"面试长短由信息量决定"另议、不急。下面三项改动都小，放行后一起做，单测为主，冒烟 1 场。

### 9.1 档位删除

`brief.level`（campus / experienced）是 9 月 13 日我自己加的，用户没有提过。全部删：`INTERVIEW_LEVELS` 与标签、简报 schema 的 `level`、备课提示词里"按 level 定难度"与第 0 条、兜底正则 `guessLevel`、`parseStoredBrief` 的校验、面试官系统提示词里"候选人档位"那句、体验版文档里的字段。旧 `briefJson` 里的 `level` 忽略。难度口径不再显式给：岗位描述本身在两处提示词里，模型按它定。

### 9.2 蓝图加业务

蓝图 schema 加 `business`（可空）：`{ product≤200（团队做什么、给谁用）, systems[≤5]≤80（核心系统或链路）, constraints≤200（规模、合规、延迟等约束）| null }`，JD 分析提示词加一条"从团队介绍与职责里整理业务：产品、核心系统或链路、约束；JD 没写的置 null，不猜"。三处用它：
- 简报：场景题优先落在 `business.systems` 之一，`jdEvidence` 规则不变；
- 面试官系统提示词人设后加一句"这个团队做：{product}"（有才加）；
- 报告页"这题在考察什么"旁显示业务链路（有才显示）。
题池抽样不动。旧蓝图没有 `business` 视为 null。

### 9.3 缓存命中率

现状：系统提示词整场不变 → 历史只追加 → 最后一条用户消息 = 现场卡 + 候选人的话。冒烟里每回合输入约 4.4k token、命中 77–80%。三处可改：
1. 历史裁剪按块：现在超过 14k 字符就从最旧一条条丢，长场每回合前缀都变、缓存全失。改成超过上限一次丢到 10k 以下，之后几回合前缀稳定。
2. 现场卡拆成单独的一条用户消息放在候选人的话之后：现在最后一条是"卡 + 话"，下一回合历史里那句话是裸的，前缀在这里断开，每回合白丢一条；拆开后前缀能多匹配一条。
3. `prompt_cache_key` = 会话 id（AI SDK 的 `providerOptions.openai.promptCacheKey`）：同一场的请求路由到同一缓存分片，命中更稳。
不做：把时钟或笔记放进系统提示词（每回合变，缓存全失）。预期命中率上限约 85–90%（每回合必然新增：卡、笔记、候选人的话）。

### 9.4 执行记录

## 10. 面试长短由信息量决定：时间盒 → 覆盖配额（2026-09-16 讨论定稿，同日放行开工）

用户的判断：不能保证用户连续完成一场面试，面试长短应由"面试官拿到了多少信息"决定，不由分钟数决定。讨论后定：按默认配额、要"问够了"信号、语音版去掉真实时间、房间显示进度。

### 10.1 配额与预算

| 节奏 | 项目 | 基础题 | 场景题 | 最多问句数 |
|---|---|---|---|---|
| 快速 | 1 | 2 | 1 | 11 |
| 标准 | 2 | 3 | 1 | 17 |
| 深入 | 3 | 4 | 2 | 26 |

预算按种类：项目 4 句（切入 + 3 次追问）、基础题 2 句、场景题 3 句（三级阶梯）。"最多问句数"是三者相加，取代硬顶。

**项目不够配额时**（简历只有一两段经历；实习与项目都算项目——简历识别出的 `internship` 与 `project` 同样进项目材料）：缺的项目的预算平均分给现有项目，每个项目最多 6 句（切入 + 5 次追问，把"要验证的说法"问完就是深入两个方面）；分不完的不补，这场就短一点。简历没有项目的，项目配额让给基础题池（题池 4 道封顶）。

### 10.2 一份材料"够了"的四个信号

1. 预算用完（代码）。
2. 候选人连续两次答不上，或要求跳过（代码，现有规则）。
3. **模型说"这份问够了"**：面试官输出多一个布尔 `done`——要验证的点验完了，或候选人明显讲不出更多。至少问完切入问法加一次追问才认（偏早兜底）；预算兜住偏晚。这是方案里唯一交给模型判断的地方。
4. 候选人求助不算够：换个说法再问（现有规则）。

### 10.3 决策（`decideMove` 改成八条）

开场 → 配额空了就收尾 → 要求跳过换题 → 连续两次答不上换题 → 求助 / 第一次答不上继续（说具体）→ 模型说够了换题 → 这份预算用完换题 → 继续追问。换题固定换到配额里的下一份，顺序项目 → 基础题 → 场景题（真实一面的顺序，备课已按此排好）；最后一份聊完 → 告别。没有"快到时间"阶段。

### 10.4 要删和要改

- 删：`clock.ts` 整个（字数折算、语音真实时间、最少问答数、硬顶系数、三个阶段比例）、`clock_tick` 事件、语音的 `realTimeClock`、房间顶栏的钟。
- 改：现场卡"时间一行"→"进度一行"（第 n 份材料 / 共 N 份，这份还能问 k 句）；房间顶栏进度条→"第 n 份 / 共 N 份"；事件 `progress_tick { covered, quota, budgetLeft }`；复盘"时间到了还在问"→"预算用完还在问"；指标里的"时间占比"→"问句占比"；模拟器节奏参数含义不变（配额）；体验版的 `totalMinutes` 由节奏换算成配额，文档同形。
- 不变：备课、底线、事后评分、报告、失败清单与扰动。

### 10.5 验证

单测（配额与预算、项目不够时的分配、`done` 的偏早兜底、八条决策）；冒烟 2 场：`--perturb long_answers`（长回答不再吃时间）与 `--perturb dont_know`（答不上换题、配额走完收尾），各 1 场。

### 10.6 项目追问的角度：深入程度归模型、岗位相关度归备课、随机归代码

用户观察（2026-09-16）：项目深挖常只盯一个方面（Study Assistant 只问记忆）。原因：一份项目材料只有一句"顺着候选人上一句追问"，没有东西推着换角度。

- **备课**：每个项目的三个追问角度（`guides`；模型没写的用默认三条：最难的问题、效果与预期、取舍与重做）按岗位相关度排序，位置就是权重（3、2、1）。备课提示词加一句"按岗位最关心的排前"。
- **面试中，代码记账**：每个角度记"追了几句"和"模型有没有说它讲透了"。下一次追问的角度从还没讲透的角度里按权重加权随机抽，随机种子 = 会话 id（可重放）；同一个角度最多连追 2 句。
- **模型只报一个布尔 `facetDone`**：候选人刚才那段回答把当前角度讲透了，或明显讲不出更多。为真时代码立刻换角度。基础题 / 场景题上这个布尔就是"这份问够了"。
- **材料与角度都由代码指派**：面试官不再自报 `topic`（自报滞后与误报在 F1 / F2 各付过一次代价）；这句聊哪份材料、哪个角度写进 `interviewer_said`，覆盖账、切段提示、复盘都从这里取。底线"该换题没换"仍按切入问法相似度判。
- **现场卡的建议**写成"追问角度：「效果与预期……」（岗位最关心；上一个角度已讲透），从候选人刚说的话切过去"；候选人已经讲到的，模型可以直接问深一层。
- **"问够了"**：项目 = 所有角度都讲透或预算用完；基础题 / 场景题 = `facetDone` 或预算用完。
- 不做：让模型自己在建议之外挑角度并自报——没有证据前不开。

### 10.7 执行记录（2026-09-16）

按 §10.1–10.6 做了：`progress.ts`（配额、预算、进度、角度抽样）替代 `clock.ts`（已删，含语音真实时间）；`decide.ts` 改为八条规则、决策带 `target / ifDone`；面试官输出 `{ say, notebook, facetDone, closing }`，材料与角度由代码指派写进 `interviewer_said`；事件 `progress_tick`；现场卡"进度一行"；房间顶栏"材料 n / N"，钟删掉；trace 每回合显示角度与讲透的角度；复盘"预算用完还在问"；体验版文档去掉时长；备课提示词角度按岗位相关度排前。单测 445 通过（新增 progress.test：配额与预算、项目不够时的分配、抽角度的权重与可重放）。

冒烟 2 场（约 0.3 美元）：
- `sim:s10-long`（扎实 + 超长回答，快速档）：8 条 500 字以上的回答，配额 1 + 2 + 1 全部按预算问完（4 + 2 + 2 + 3 = 11 问），13 回合按配额结束；重复提问 0、底线 0、缓存 79%。长回答不再影响面试长短。项目的三个角度问了两个（预算 4 句、同一角度最多 2 句），第三个没轮到——快速档可接受，标准 / 深入档项目预算更大。
- `sim:s10-dontknow`（扎实 + 连续答不上，标准档）：两次"我不会"换到第二个项目，第三次"我不会"再换到基础题（连续计数不按材料分）；之后每份材料按预算走完，15 回合按配额结束；重复提问 0、底线 0、缓存 80%。模型报了一次 `facetDone`（场景题第一层讲透，代码立刻换到第二层）。

用户实测（2026-09-16）：整体好，一处失败——基础题追问后说"什么意思？"，面试官跳到了下一题。原因：决策里"预算用完"排在"求助"之前（那句追问正好用完了 2 句预算），而且答疑本身也占预算，下一题的答疑又吃掉了它的追问。修：答疑改为独立动作 `clarify`，先于预算判断；答疑那句记 `kind: aside`，不占材料预算（老指标"答疑句数"沿用 aside）。只加单测，不跑场。
