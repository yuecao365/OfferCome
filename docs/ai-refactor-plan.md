# AI 模拟面试与能力画像重构计划

2026-08-17，基于真实使用反馈制定。核心矛盾：当前管线用"链式硬校验"保证严谨性，代价是频繁产出**零结果**；而产品北极星是端到端、宁可降级产出也不把死胡同丢给用户。

---

## 0. 触发问题诊断：为什么反复点"AI 补全"没用

用户看到的错误「岗位能力分析没有完成。模型没有返回可用的结构化结果」来自**岗位分析（蓝图）阶段**，而"让 AI 补全"按钮触发的补全（enrich）在流水线里位于蓝图**之后**：

```
重试(enrich) → 重跑蓝图分析 ──失败──> 同样的报错（补全根本没执行到）
                    └─成功──> 补全 → 出题
```

蓝图分析是全管线**唯一没有任何降级的环节**：无残缺 JSON 抢救（rescue）、无简化重试、无兜底产物。严格 schema（嵌套结构 + 每字段长度上限 + jdEvidence 逐字要求）遇上 gpt-4.1-mini 级别的模型和长 JD，结构化输出失败率高，且每次重试都在原样重复同一个必败调用。按钮的承诺（补全）与真实故障点（分析）错位，形成死循环。

这不是孤立 bug，是设计取向问题：**验证失败的默认动作是"拒绝并要求用户重试"，而不是"降级并继续"**。

## 1. 设计原则：验证分级

把现有的每一道校验重新归类，只允许三种处置：

| 级别 | 处置 | 保留哪些 |
|---|---|---|
| **硬门**（失败即拒） | 拒绝该条数据 | 仅三类：① 注入防护（输入当数据、指令忽略）；② 引用真实性（凡是**声称**引自原文/搜索结果的内容必须真实存在，否则清空引用字段，不许伪造）；③ 写入原子性（状态机、事务） |
| **软门**（失败即降权） | 排序靠后 / 打标降权，不丢弃 | 配额、相关性分、题目数量、去重相似度 |
| **标注**（失败即透明） | 保留产物 + 给用户/日志留痕 | 逐字证据退化为意译、通用补全占比、少题差额 |

**永不空手定律**：每个 AI 环节必须有降级链，链尾是"可用的产物 + 一句透明说明"，绝不以"请重试"收场。

判断口径：**报错打断用户 = 工程问题，必须修；内容质量波动 = 用标注和透明度处理，不用拦截处理。**

## 2. AI 模拟面试重构

### 目的重述

用户给岗位 + 简历 → 得到一场**贴合岗位、可作答、可评分、可复盘**的面试。防幻觉、防注入、可恢复都是手段；手段不能反噬目的（一场稍有瑕疵的面试远好于没有面试）。

### 现管线评估

**优点（保留）**：注入防护一致；评分 rubric 出题时预生成（逐题公平）；DB 状态机可断点续跑；结构化日志可回溯；证据可溯源。

**缺点（本次要改）**：
1. 验证是串联硬门（蓝图 schema → 逐字证据 → 配额 → 恰好 N 题 → seed 必含），失败率相乘，任何一环失败 = 全无；
2. 蓝图环节零降级（见 §0）；
3. 出题 schema 要求**恰好 N 题**（`createQuestionOutputSchema(questionCount)`），对小模型极脆；
4. 配额规则在 system prompt 和 `selectValidQuestions` 写了两份，改一处漏一处；
5. 失败 UX 是死胡同，按钮语义与故障点错位。

### P0：消灭死胡同（约 1 天）

1. **蓝图四级降级链**：严格 schema → runAgent `rescue` 抢救残缺 JSON → 简化 schema 重试一次（去嵌套、放宽长度）→ **兜底蓝图**（由岗位名生成 3-5 条 `origin=inferred` 通用能力，复用 enrich 的既有标注语义）。蓝图环节从此**不可能失败**，§0 的死循环整体消失。
2. **题目数量软化**：schema 改为 3..N 区间；筛选后 ≥ max(3, ⌈0.6N⌉) 即开场，差额在房间里一句话说明（"本场生成了 6 题"）；低于下限才补货一次，仍不足就带着已有题开场而不是报错。
3. **失败卡片语义修正**：动作按钮按真实失败阶段生成（做完第 1 条后该卡片基本只剩"模型服务不可达"一种情形）。

### P1：软门化（2–3 天）

1. `selectValidQuestions` 拒收逻辑改为**打分排序**（`rankQuestions`）：硬拒只留"伪造引用类"（competencyId 不存在、resumeProjectId 不存在、personalizationSourceId 不在输入内）；重复、配额超额、相关性弱一律变成排序扣分，取 top-N。
2. **jdEvidence 逐字失败 → 标注不丢弃**：`evidenceKind: "verbatim" | "paraphrased"`，意译降相关性权重；蓝图 `cleanBlueprint` 同理（意译的能力保留但降级为 secondary）。
3. **配额单一来源**：从"prompt 写一份 + 代码强制一份"改为一张权重表，prompt 里只描述倾向，排序时兑现。
4. **JD 薄不再暂停**（吸收原 B1）：`awaiting_jd_review` 仅在"JD 几乎为空"时出现；一般偏薄直接自动 enrich 继续，报告页透明卡显示"X 题直连 JD / Y 题按岗位常见要求补全"。
5. **失败自动重试一次**（静默、简化上下文）再打扰用户。

### P2：自主性增强（择机）

- 出题 agent 工具化：把预筛好的历史/画像上下文（`selectRelevantPersonalization` 预打包）改为给 agent `search_history` / `query_profile` 两个工具，自主决定查什么、用不用——上限和防注入仍在代码里。
- 追问预算交给 agent 判断（每题 0–2 次，上限仍由 `follow-up-policy` 代码持有）。

### 质量底线怎么守

旧硬门不是删除而是**降级为离线指标**：`logAgentRun` 已记录 accepted/rejected，补充 paraphrased 率、通用题占比、少题率三个 metrics 字段。上线后观察一周，若意译率异常升高再针对性收紧——用数据决定松紧，而不是预先全拦。这与既有的 eval 体系计划（golden set 回归）直接衔接。

## 3. 能力画像重构

### 目的重述

从历史面试（真实 + 模拟）中告诉用户：**哪里不错要保持、哪里薄弱怎么练**。数字和维度是手段，教练式反馈是目的。

### 现状为什么"鸡肋"

1. **冷启动全空**：每个维度要 ≥2 场有效面试、趋势要 3 个不同天，新用户看到的是一排"待积累"空表盘——最需要反馈的时候什么都不给；
2. **8 维平铺过细**：数据稀疏时每维只有一两个观察点，1–5 分的加权数字既不稳定也不可解释；
3. **洞察被引用规则勒死**：合成 agent 只能复述已验证观察（必须引用 observationId），说不出跨场模式，输出趋于空泛；
4. **稀疏信号维度拖后腿**：`delivery_fluency` 只有录音才有数据、`reflection_growth` 逐题几乎观察不到，常年空置显得整页残缺。

### 8 维合理性评估

| 维度 | 评价 | 处置 |
|---|---|---|
| knowledge_accuracy / reasoning_depth / problem_solving | 内容硬实力，观察点充足 | 保留，归入**内容力** |
| answer_relevance / experience_evidence | 应试与证据能力，观察点充足 | 保留，归入**证据力** |
| communication_clarity | 文本可观察 | 保留，归入**表达力** |
| delivery_fluency | 仅录音可观察，稀疏 | 保留为**表达力**子信号，无数据时不显示、不占位 |
| reflection_growth | 逐题几乎无法观察，长期空置 | **降级为洞察信号**（合成 agent 在跨场层面判断），不再单独打分 |

底层观察数据不动（8 维照存），改的是**聚合与呈现**——历史数据零迁移。

### P0：冷启动叙事化（约 1 天）

门槛不足时页面不再显示空表盘，改为"近期定性反馈"卡：聚合最近 N 场的逐题反馈（数据现成，模拟面试逐题评分已有 strengths/improvements），每条弱点带"针对练习"按钮（seed 机制现成）。有一场面试就有可看的内容。

### P1：分组呈现 + 洞察松绑（1–2 天）

1. 页面按 **内容力 / 证据力 / 表达力** 三组呈现，组内子维度作为明细展开；
2. 门槛下放：1 场即出"初步印象"（tentative 标注），3 场转正式；趋势判定顺带修掉 UTC 日期分桶 bug（按本地时区算天）；
3. 洞察 agent 松绑：允许提出跨场模式**假设**（标注"待验证·基于 N 场"）；引用粒度从 observationId 放宽到 interview+question；语气从证据陈述改为教练反馈——每条洞察必须落在"继续保持什么"或"练什么、怎么练"上，训练建议直接挂一键练习。

## 4. 其他功能的顺带结论

- **导入/复盘/Boss 同步**：方向已对齐（自动推断、部分交付、如实报差额），不动；
- **导入的 unmatched 数量**加进 agent 日志 metrics，与出题的拒收率同板观察；
- 原六批路线图中的批次 3（JD 兜底）与批次 5（画像冲突）被本计划吸收；批次 1/2/4/6 维持原样待做。

## 5. 明确不做

- 不放开注入防护；不允许模型改写内容冒充原文引用（引用真实性是硬门）；
- 评分 rubric 仍在出题时预生成（公平性基石）；
- 不引入多 agent 自由会话、不迁移框架；
- 画像不做数据库迁移（只改聚合与呈现层）。

## 6. 实施顺序

| 批次 | 内容 | 预估 |
|---|---|---|
| 1 | 面试 P0（蓝图降级链、数量软化、失败卡修正） | 1 天 |
| 2 | 画像 P0（冷启动叙事卡） | 1 天 |
| 3 | 面试 P1（rank 化、标注化、JD 薄自动补全、静默重试） | 2–3 天 |
| 4 | 画像 P1（三组呈现、门槛下放、洞察松绑） | 1–2 天 |
| 5 | 面试 P2（工具化出题）——观察 1/3 批效果后再定 | 择机 |
