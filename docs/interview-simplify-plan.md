# 面试流程简化计划（备课广度优先 · 卡住由代码接管 · 先决定再说话）

> 基于三份流程文档描述的现状（interviewer-v4 / brief-v7）与用户 2026-09-10 在网页版跑的一场标准节奏面试（字节 AI 全栈实习，trace 见对话记录）。用户定的方向：**简化，不打补丁**；对质时要给候选人复查简历等资料的工具。
> 2026-09-10 第一稿。只读代码，未改代码。
> 执行状态：§8 三点按建议定；第 1 步已完成（2026-09-10），见文末执行记录。

## 0. 那场面试暴露的三条主线

| 现象 | 机制 |
|---|---|
| 标准节奏只考了 3 个方向，其中 2 个围绕同一个项目；JD 里社交/通讯场景、AI 集成、CS 基础一个没碰 | 备课按"每领域 depth+2 回合"装箱，模型给的 depth 3–4，20 回合只装得下 3 个领域；"至少一个 project 领域"和"technical 领域从项目切入"让两个领域挂在同一个项目上；JD 原文虽然在备课与回合的提示词里，但没有任何指令要求把 JD 的具体场景变成题 |
| "不懂 / 提示 / 不会"连续三回合，面试官解释三次（把答案讲完）才换题；候选人说"简历瞎写的"后面试官没对质 | 卡住被当成"需要模型即兴处理的对话"：提示 1 次 + 澄清 2 次的预算，用完后只能"只说话"，直到"连续 2 回合无推进"才被代码强制关线程；提示的信息量没有限制 |
| 跳过的题又被问一遍；"抱歉刚才重复请求了自我介绍"后面接了一道题 | 每领域允许 2 条线程，跳过的领域仍算可开；模型没给动作时代码兜底"回访一个领域"，并把代码的切入问题拼进模型的话里 |
| 面试官的话先出一段、消失、再出另一段 | 模型在同一次调用里先说话、再调工具、再说话；前端每个 step 清空流式文本，代码取最后一步的话 |

删掉的机制比新增的多：澄清、打断、"只说话"消息、每线程三个计数器、空转强制推进、领域回访、话语拼接、"取最后一步的话"。保留：领域与阶梯、追问锚点、信息量收尾、工作记忆、切段及之后的一切。

## 1. 原则

1. **面试官的自由只在"问什么、往哪追"；流程分支归代码。** 开场、卡住、跳过、否定简历、收尾都是确定的分支，模型只负责把代码定下的动作说成人话。
2. **每个领域一次机会。** 一条线程问完就结束，不回访；广度靠备课保证，不靠面试中补。
3. **先决定，再说话。** 一回合两步：动作与记忆用工具给出，然后只输出给候选人的话；流式只有第二步。
4. **JD 是题目的来源之一，不只是背景。** 备课要把 JD 的具体场景写进领域的切入问题；简报里每个领域都标明来自 JD 的哪一句或技能包的哪个主题。

## 2. 备课：广度优先

### 现状
`brief.ts` 按 `depth + 2` 装箱；quick 10 / standard 20 / deep 32 回合；模型自填 depth 1–4 与权重；"至少一个 project 领域围绕项目深挖，project 最多两个"；technical 领域可以从项目场景切入；装箱丢弃的领域不告诉用户。

### 改动
- 每个领域花费固定 `depth + 1`（切入 + 追问，提示不再占回合），深度封顶 2（quick）/ 3（standard、deep）；领域数下限 quick 3、standard 4、deep 5，上限 6。装不下时先降深度再丢领域，不再只按权重丢。
- 选材规则（写进提示词，代码校验）：
  - 每个简历项目最多一个领域（kind=project）；代码按 `projects[].id` 去重，第二个挂在同一项目上的领域直接丢弃。
  - technical 领域必须绑定蓝图能力或技能包主题，切入问题不得以"你在 X 项目里"开头；代码用简历项目名做子串检查，命中的 technical 领域转成 project 领域或丢弃。
  - 每个 JD 来源的领域带 `jdEvidence`（JD 原文逐字片段，与蓝图同一道硬门），切入问题要落到这一句描述的场景；缺 evidence 的领域降为基线。
- 简报存 `droppedAreas`（装箱丢掉的领域名），报告页"考察领域"下一行"这场没问到：…"，让用户知道面试为什么没覆盖到某方向。

### 删除
`ensureTwoAreas` 的补第二领域逻辑（下限由装箱保证）、"至少两个 fundamentals 领域"这条硬性配额（按用户定的原则，八股不是目标；基线领域由模型按 JD 缺口补）。

## 3. 面试中：动作集缩到五个

### 现状
8 个动作 + note + load_skill；候选人意图分硬（跳过 / 重复 / 结束，代码执行）与软（提示 / 澄清，只作信号）；每线程提示 1、澄清 2、打断 1；每领域 2 条线程；空转 2 回合强制推进；兜底动作可回访领域并把切入问题拼进模型的话。

### 改动：动作与分支

| 动作 | 谁决定 | 说明 |
|---|---|---|
| ask_intro | 代码 | 开场固定，模型只写话 |
| open_thread(areaId, question) | 模型 | 只能开未考察的领域；question 必须与该领域相关（代码不校验内容，只校验 areaId） |
| probe(anchor, question) | 模型 | 不变：锚点硬门、深度上限 |
| hint(hint) | 代码触发、模型写内容 | 候选人卡住且本线程没提示过：提示词限定"只给方向或缩小范围，不给答案、不举完整例子，≤ 80 字"；代码按长度截断兜底 |
| close_thread(note) | 模型或代码 | 不变；之后必须紧接 open_thread 或 close_interview（模型给或代码给） |
| close_interview | 模型或代码 | 不变 |

候选人插话全部由代码判定并执行，模型不再收到"信号"去自行选择：

| 候选人说 | 代码分支 |
|---|---|
| 跳过 | 关线程（skipped）→ 开下一领域。过渡话固定 |
| 再说一遍 | 复述上一问，不调模型 |
| 结束 | close_interview |
| 不会 / 不懂 / 要提示 / 想考什么（现在的 hint 与 clarify 两类合一） | 本线程没提示过 → 模型给一次 hint；已提示过 → 关线程记失守（note 固定"候选人卡住"）→ 开下一领域，过渡话固定 |
| 否定简历内容（"瞎写的""没做过""不是我做的"） | 记忆 failed + 对应假设 refuted；关线程记失守；同一项目的其余领域标记跳过；开下一领域。面试官的话由模型写：对质，并**逐字引用简历里的那一句** |

删掉：clarify、interrupt、aside 消息类型、`rescues / clarifies / interrupts` 三个计数器（线程只留 `hinted: boolean`）、`IDLE_TURNS_BEFORE_FORCE` 与空转规则、`THREADS_PER_AREA` 与领域回访、`utterance()` 拼接、`CANDIDATE_INTENT_SIGNALS`。兜底只剩两种：模型没给可用动作 → 关线程并开下一领域 / 收尾。

### 改动：一回合两步（`turn-agent.ts`）
- 第 1 步 `toolChoice: "required"`：只允许 note、load_skill 和推进动作，最多 3 步（查包 ≤ 2 次 + 动作）；输出文本被丢弃。
- 第 2 步 `toolChoice: "none"`：提示词告诉模型"你已决定 X（动作与入参），现在对候选人说话"，只输出文本，流式返回。
- 代码在两步之间做裁决：动作不被允许就换成确定性动作，再让模型照着说；模型因此永远在为"最终动作"说话，不需要拼接。
- 决策记录不变；`decisionFromOutcome` 里"取最后一步的话"删除。

### 改动：候选人的资料抽屉（用户要求）
房间顶栏加"资料"按钮，打开抽屉显示本场的简历原文与岗位描述（都是会话快照，本地版 `resumeTextSnapshot` / `jdTextSnapshot`，体验版文档里的 `resume.text` / `job.jobDescription`）。面试官对质时引用的简历原句在抽屉里高亮（消息带 `quote` 字段，前端按逐字匹配定位）。候选人随时可以打开核对自己写了什么，不影响面试进程，也不进评分。

### 提示词（interviewer-v5）
- 第 1 步：人设、信息量、领域与阶梯、当前线程、工作记忆、技能包索引、允许的动作；去掉关于澄清 / 打断 / 提示时机的所有说明。
- 第 2 步：给定动作后的说话规则：先回应（追认 / 纠偏 / 对质三选一），再提问；对质要逐字引用简历；hint 只给方向；跳过与卡住换题时的过渡话由代码固定，不调模型。
- 岗位描述节选保留，并加一句：追问可以把 JD 里的场景（团队介绍、职责里的具体系统）作为情境引入。

## 4. 面试后：不动，两处顺带

- 切段的 `metadata.rescues` 改为 `hinted`；评分提示词里"追到第 n 层答不上属正常"不变。
- 类目文案：`technical` 显示"技术题"（不再叫八股）；复盘与报告用领域名 + 风格（项目 / 场景 / 基础 / 行为）而不是类目。

## 5. 数据与兼容

- 简报 `version: 5`：领域加 `jdEvidence: string | null`、简报加 `droppedAreas: string[]`；旧简报读出时两者为空。
- `InterviewThread`：`rescues / clarifies / interrupts` 三列合并为 `hinted Boolean`（schema 改动，`db push`）；进行中的旧会话很少，直接迁移为 `hinted = rescues > 0`。
- 消息 kind 去掉 `clarify / interrupt / aside`，候选人侧去掉 `question`（卡住的话记为 `aside`）；已落库的旧 kind 只在对话记录里原样显示。
- 体验版会话文档随线程形状一起升版本（v4，旧文档丢弃，既定策略）。
- 提示词版本 interviewer-v5、brief-v8。

## 6. 评测钩子（不扩框架，只改口径）

| 指标 | 变化 |
|---|---|
| 追问贴合率、锚点命中率、失守识别 / 进报告、对照误报、假设覆盖 / 被追 | 不变 |
| 澄清占比、空转率 | 删除（机制不存在了） |
| 动作替换率、每场强制推进次数 | 保留，语义变为"模型动作不可用、代码兜底"的次数 |
| 新增：卡住后换题回合数 | 从"候选人第一次说不会"到"开下一领域"的回合数，期望 ≤ 2（一次提示 + 换题） |
| 备课：领域数、每个简历项目的领域数、technical 领域中带 jdEvidence 的比例 | 从简报直接算，不需要裁判 |

面试官评测的静态脚本 `hints.json`（连续要提示）正好验证卡住分支；`longform`、`injection` 照跑。覆盖率只作门禁。

## 7. 实施顺序与验收

| 步 | 内容 | 验收 |
|---|---|---|
| 1 | 备课广度优先（§2）+ brief-v8 | 单测：项目去重、technical 不挂项目、jdEvidence 硬门、装箱下限；`coverage --k 4` 不掉出噪声；5 份 JD 各备一次课人工看领域清单：标准节奏 ≥ 4 个方向、同一项目只出现一次、每个 JD 领域能指回 JD 原句 |
| 2 | 动作集缩减 + 候选人分支归代码（§3 前两节）+ 线程 schema | reducer 单测覆盖每条分支；`interviewer --k 2 --cases hints,persona-1,persona-2,control-1`：卡住后换题回合数 ≤ 2，替换率不高于现在，其余指标在噪声内 |
| 3 | 一回合两步（§3 第三节）+ interviewer-v5 | 真机：面试官的话一次出完，不再闪烁；trace 里每回合有动作与话语两条记录；token / 耗时记基线 |
| 4 | 资料抽屉 + 对质引用（§3 第四节）+ 文案（§4） | 真机：对质消息里的简历原句在抽屉里高亮；两端同一个组件 |
| 5 | 流程文档原地更新、评测口径（§6）、体验版文档版本 | `npm test`、`tsc`、`eslint` 全绿；体验版端到端脚本跑通 |

预估 3 天：第 1 步 0.5，第 2 步 1，第 3 步 0.5，第 4 步 0.5，第 5 步 0.5；每步独立提交。第 2、3 步动的是核心，先做第 1 步是因为它独立且能立刻改善下一场的观感。

## 8. 待你定

1. 卡住的路径是"一次提示后换题"（建议），还是"一次提示后降一级再问一次"再换题。后者多一次机会，但多一个分支。
2. 对质之后同一项目的其余领域直接跳过（建议），还是照问但降低权重。
3. 资料抽屉里除了简历与 JD，要不要放"这场的考察领域"给候选人看。我建议不放：面试中不该看到面试官的计划，报告页再揭晓。
