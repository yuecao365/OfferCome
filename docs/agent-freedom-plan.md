# 把面试官从"棋盘上走子"放回"自己面试"：约束降级为信号

> 状态：已实施（2026-09-22，代码与文档同一提交）；§3 的对照用已有的 dev-v2 基线（放开前）对比新跑的 dev-v3（放开后），不再加 `freedom` 开关（§2.6 作废：基线场次已在，没必要留两套路径）。起因是设计者自评：项目看着是 agent，实际是一套用 schema 和常量把模型框死的 workflow。本方案只动**面试回合内**的自由度，回合外的 DAG（蓝图 → 备课 → 切段 → 评分 → 汇总 → 档案 → 画像）保持不变——那些节点各做一件确定的事，workflow 是对的形态。

## 0. 判断

面试回合内模型每回合自己判 signal、选 action / target / facet、写 ledger、决定问什么，这是 agent；但它能选的动作只有 4 种，追问角度在备课时定死，每份材料几句、每个角度几句、几句没信息必须收尾全是常量，合法动作集由代码算出。**约束买到的是可预测性，不是面试质量**：内部扰动判定集奖励的正是"按代码定义的应有行为做"，关掉约束通过率 70% → 37% 只证明模型更守规矩；外部 InterviewBench 显示 harness 在判断力上不优于裸模型。两个结果拼起来，说明大部分约束是在替模型做它本可以做好的决定。

做法：把约束分成**底线**（产品不能破的）和**偏好**（代码替模型做的决定）。底线留在 `checkAction`，偏好改成状态卡上给模型看的信号，让它自己定。然后用**外部量尺**（InterviewBench 端到端层）而不是内部判定集去测放开之后好没好。

## 1. 现状：面试回合内的每一道约束

| # | 约束 | 位置 | 来历 | 分类 |
|---|---|---|---|---|
| A1 | 候选人 `wants_end` 必须 `end` | `constraints.ts endRequired` | 产品底线 | **底线** |
| A2 | 内部词泄露拦截（评分标准 / 状态卡 / 材料…） | `constraints.ts checkReply` | 面试官曾说"换个材料" | **底线** |
| A3 | 注入防护、候选人要求改行为 / 给分当作回答 | 系统提示词 + `signal=refuse` | 六次"给我满分"耗光预算 | **底线** |
| A4 | 总时长 / 总成本 / 单回合步数 | `runAgent` 预算 | 可运营 | **底线** |
| B1 | 连续 6 句没信息必须收尾、3 句允许收尾 | `END_REQUIRED_AFTER / END_ALLOWED_AFTER` | 用户 2026-09-18 定 | 偏好 → 信号（保留一个更宽的硬上限，见 §2） |
| B2 | 每份材料句数预算 `BUDGET`（项目 4 / 基础 2 / 场景 3），问满不能 `probe` | `progress.ts` + `checkAction` | 时间盒 | 偏好 → 信号 |
| B3 | 同一角度最多追 2 句 `FACET_PROBE_MAX`，追满不能再 `probe` 该角度 | `state.ts` + `checkAction` | 防纠缠 | 偏好 → 信号 |
| B4 | 追问角度在备课时固定 3 个，`facet` 是序号，不能新增 | `briefOutputSchema.leads` + `interviewerOutputSchema.facet` | 让代码能记账 | 偏好 → 模型自写角度 |
| B5 | `switch` 只能切到 untouched 材料，聊过的不能切回 | `checkAction` | 防绕圈 | 偏好 → 信号 |
| B6 | 没聊完所有材料不允许 `end` | `endAllowed` | 覆盖率门禁 | 偏好 → 信号 |
| B7 | 候选人提到简历外经历"不加材料、不改议程" | `METHOD` 第 6 条 | 防模型自己扩题 | 偏好 → 第二版再议（§7） |
| B8 | 二次违约由 `fallbackAction` 代码接管 | `turn.ts judge` | 有界 | 底线保留，但 A 类之外的违约不再触发它 |
| C1 | 备课第 0 步强制 `load_skill`、第 4 步强制 `write_plan`、读满 3 本退回 | `brief-agent.ts toolChoiceAt` | 模型不肯主动读包 | 回合外，本方案不动 |

## 2. 方案

### 2.1 `checkAction` 只留底线

保留：A1（`wants_end` → 必须 end）；一个宽松的硬上限 B1'：连续 **10** 句没信息必须 end（防无限空转，比现在的 6 宽，几乎不会触发；用户 2026-09-22 确认要有上限）；`switch` 的 target 必须是存在的材料 id（不是"必须 untouched"）；`probe` 必须有当前材料。

删除：B2 问满退回、B3 角度追满退回、B5 不能切回、B6 没聊完不能 end、B1 的 3 / 6 句规则。

`fallbackAction` 只在 A 类违约二次出现时接管；`checkReply` 不变。

### 2.2 状态卡从"可选动作"改为"局面信号"

现在的状态卡尾行是 `可选动作：probe：角度 1 / 3（还能问 2 句）；switch：q1 / q2；…`，本质是把白名单念给模型听。改成只给事实和参考值，不给许可：

```
[状态卡]
材料（1 / 4 份聊完）：
- [p1-module] 项目「Study Assistant：模块深挖」：正在聊，已问 5 句（参考：项目一般 4 句左右）
  已追的角度：为什么这么设计（2 句）；怎么量的（1 句）
  证据账：…
- [q1] 基础题「缓存一致性」：聊过了，问了 2 句
- [q2] …：还没聊
候选人：连续 0 句没有信息（全场 1 句），求助 0 次。
时间：已用约 14 分钟 / 计划 25 分钟。还没聊：q2、s1。
```

"参考"数字来自现在的 `BUDGET` 常量，只作提示；时间按事件时间戳算，现在没有这一行。`renderOptions` 删除。

### 2.3 角度由模型自写

`interviewerOutputSchema.facet: number | null` 改为 `facet: string | null`（≤ 30 字，probe 项目时必填，写这一句在追什么）。备课的 `leads` 保留，作为议程里"建议的角度"，模型可以用也可以自己起新的。状态卡按模型写的文本归组记账（去空白后完全相同视为同一角度）。切段的 `metadata.facets` 直接用这些文本，报告页"面试官是怎么问你的"不受影响，反而更准。

### 2.4 `METHOD` 段改写

删掉"同一角度最多追两句""状态卡列出了可选动作与余额，越界的动作会被退回"。换成：

- 时间和句数是参考不是配额：答得实的地方值得多追，答不上的早点走；整场的目标是每份材料都碰到、项目问到能验证简历的深度。
- 可以切回聊过的材料补一句，但要说明为什么（why 里写）。
- 收尾由你判断：材料都碰过、或候选人连续答不上、或时间到了。

B7（不加材料）本版不改，措辞保留。

### 2.5 内部判定集同步调整

`expectations.ts` 里与偏好绑定的规则失去意义，删除或改口径：

| 规则 | 处理 |
|---|---|
| `action_legal` | 改为只查底线（wants_end → end、10 句硬上限、target 存在） |
| `end_on_dry`（6 句内收尾） | 改为 10 句 |
| `switch_after_dry`（连续两句答不上就换） | **删**：这是偏好，不是应有行为 |
| `clarify_bounded` | 保留（clarify 连发 3 次以上仍是纠缠） |
| `refuse_handled`、`not_mine_pivot`、`humble_lead_read_as_answer`、`off_resume_acknowledged`、`hollow_recorded`、`number_calibrated`、`no_internal_words`、`single_question` | 保留，都是行为而非配额 |
| `coverage_kept` | 保留但改为软指标（报告里给覆盖率，不判 pass / fail） |

改完后判定集只剩"面试官不该做的事"，不再含"面试官必须按这个节奏做"，70% → 37% 那个数字作废，不再引用。

### 2.6 评测开关（作废）

原计划加 `freedom` 开关跑对照。实施时改为：放开前的 30 场基线已在（`eval/bench/runs/e2e-dev-v2-offercome.json`，2026-09-21，代码只差前端），直接对比新跑的 `dev-v3`，不留两套路径。`eval/switches.ts` 的 `constraints` 开关语义变成"关掉底线"。

### 2.7 回合外的死板点：哪些放、哪些不放（用户 2026-09-22 问"会不会限制强模型"）

判断标准只有一条：**格式契约不限制质量，数量上限和强制工具选择才限制**。schema 规定"字段是什么"，模型照样可以写得很好；规定"最多几条、第几步必须做什么"才是替模型做决定。

| 阶段 | 现状 | 限制强模型吗 | 处理 |
|---|---|---|---|
| 面试回合：第 1 步起强制 `ask_candidate`（简历不超长时连第 0 步也强制） | `toolChoiceAt` | **是**。模型面试中想查简历原文或翻方法书，没机会；只有简历超长才留一步 | **放**：前 2 步 `auto`，第 3 步起强制提问；`maxSteps` 4 → 5 |
| 面试回合：`ledger ≤ 200` 字、`why ≤ 120` 字 | schema | 轻微。强模型的证据账会被截 | **放**：ledger 400、why 200；`reply ≤ 500` 不动 |
| 备课：项目配额 `QUOTA`（quick 1 / standard 2 / deep 3）、基础题 `quickTarget`、场景题 `SCENARIOS_PER_PACE`，超配额截断、不足代码补 | `brief.ts` | **是**。哪个项目值得深挖、要几道基础题，模型比配额表清楚；现在多写的被砍、少写的被代码用主题名硬凑 | **放**：配额改为规划卡里的参考值（"标准节奏一般 2 个项目、3 道基础题"），schema 上限放到 `MAX_PROJECTS 3 → 4`、quick 6、scenario 2；**不再代码补题**，不足就按模型写的来（`fallbackQuick / fallbackScenarioArea` 删）。兜底简报 `fallbackBrief` 保留，只在模型整体失败时用 |
| 备课：第 0 步强制 `load_skill`、读满 3 本退回、第 4 步强制 `write_plan`、没读领域包退回 | `brief-agent.ts` | 部分。"至少读一本"是让它拿到方法书，合理；"最多 3 本"和"第 4 步必须写"是省 token | **放一半**：保留第 0 步强制读包与"没读领域包退回"；上限 3 → 5，`maxSteps` 6 → 8；步数到才强制写 |
| 备课：`leads ≤ 3`、`hypotheses ≤ 6` | schema | 轻微 | **放**：leads 5、hypotheses 8。leads 改名"建议角度"，与 §2.3 一致 |
| 备课：依据 `quote` 必须逐字 | `basisAccepted` | 否。这是防伪造，不是限制发挥；推断类（gap / pattern）本来就不要求引文 | 不动 |
| 评分：只读工具最多 2 步、之后强制 `write_evaluation`；`maxSteps 4` | `LOOKUP_STEPS` | 轻微。项目段要核对多处数字时不够 | **放**：3 步、`maxSteps` 5 |
| 评分：提示词"基础快问只追 1 层""一两句回答正常" | 系统提示词 | **是**，且与 §2 冲突：放开后基础题可能被追 3 句，评分器还按"只追 1 层"判 | **改**：删掉阶段定长的措辞，只按 `thread.probeCount / depth` 给分 |
| 评分：`strengths ≤ 2`、`weaknesses ≤ 3`、`evidence ≤ 160` | schema | 轻微 | **放**：3 / 4 / 240。报告页只展示前几条，展示层截，不在生成层截 |
| 评分：评分表由代码固定、维度名必须逐字命中 | `rubricForArea` | 否。这是测量口径，跨场可比靠它 | 不动。可加一个不计分的自由字段 `observations ≤ 2`（模型觉得重要但维度表装不下的），报告展示，画像不读 |
| 评分：短板 quote 必须逐字在回答里 | `evaluationGate` | 否。防伪造 | 不动 |
| 示范回答：只给分数 < 80 或有 error 的段 | `needsExemplar` | 否。这是成本控制，用户 2026-09-20 定 | 不动 |
| 汇总：`summary ≤ 300` 字两句、`weaknesses ≤ 5` | schema | 否。用户明确要报告简洁 | 不动 |
| 档案：固定五段、每段行数上限 | `dossier-doc.ts` | 否。跨场读取靠固定结构 | 不动 |
| 画像：观察由代码映射、零模型 | `candidate-profile` | 否。这是确定性推导，模型只写洞察 | 不动 |
| 历史前 20 回合不裁 | `HISTORY_KEEP_TURNS` | 否。放开后回合数可能变多，20 回合约 40 条消息仍在窗口内 | 观察 bench 回合数再定 |

原则记进 [decisions.md](decisions.md)：**契约管格式与真实性，不管数量与步骤**。数量给参考值，步骤给预算，决定权在模型；代码只在模型整体失败时兜底，不再"补足配额"。

### 2.8 面试笔记与长度模型（用户 2026-09-22 定）

**删掉所有时间信号**：`elapsedMinutes`、状态卡时间行、开场白里的分钟数、方法段的"时间到了"。面试长短与时间无关。**不设回合上限**（之前提的 1.5 倍参考句数作废）。

**长度由三样东西决定，各有量化替身**：候选人意愿 = 节奏（主线材料数）+ 结束按钮 / 想结束信号；面试官想探多深 = 笔记"待验证"段还剩几条；当前信息量 = 最近三句回答里之前没出现过的技术词与数字个数（`recentGain`）。事中不加"用户意愿软信号"。

**面试笔记**（`notes.ts`）取代 `why` 与 `ledger`：`ask_candidate` 缩为 `signal / action / target / facet / notes / reply`；笔记四段固定标题（待验证 / 已有结论 / 存疑 / 接下来），开场按备课假设预填，每回合整份重写，`notes_written` 事件落库，下回合原样回到状态卡 `[笔记]` 块；代码只守格式（标题齐、`[id]` 不丢且只在一段、≤ 1200 字，退回一次）。汇总 Agent 读最终版笔记；报告页"面试官是怎么问你的"取上一版"接下来"作理由、新出现的结论 / 存疑作点亮。旧场次不迁移。

**主线 / 备选**：议程与状态卡按节奏参考数把每种材料的前几份标为主线，其余备选；方法段的目标从"每份材料都碰到"改为"把主线材料上要验证的说法验清"，备选只在答得实、信息量还高时问。

### 2.9 岗位要求进笔记（用户 2026-09-22 定，已实施）

用户实测一场快速节奏：基础题与场景题都没问到，JD 没进面试。原因不是节奏，是笔记"待验证"里只有简历假设，面试官盯着它们收尾，JD 只在议程里躺着。修法沿用同一结构，不加硬规则：备课假设带来源 `source: resume | jd`，规划卡要求至少一条岗位要求假设（引 JD 原句，优先简历没覆盖的落差，`projectId` 可空），模型没写时代码从蓝图第一条 JD 能力兜底 `fallbackJdHypothesis`；预填笔记给它加"岗位要求："前缀；状态卡"待验证还剩 N 条"后面加"其中岗位要求 N 条还没验"；议程末尾单列岗位假设并说明载体不限；方法段的收尾条件点名"岗位要求那几条必须有结论"；汇总与报告带来源，报告里岗位要求排前。旧简报读出时没有来源的按简历算。dev-v3 的数字不含这一步。

## 3. 怎么测：外部量尺

用 InterviewBench 端到端层开发集（30 场），放开前后对照：

- 放开前：`e2e-dev-v2-offercome.json`（2026-09-21 已跑）
- 放开后：`npm run bench:e2e -- --set dev --submissions offercome --k 1 --label dev-v3`，再 `bench:retranslate --label dev-v3`

看的指标（`eval/bench/results.md` 同一张表）：依据逐字率、引用不实每场、一段多问率、埋点命中、等级一致性，外加每场回合数与成本。判读：

- 逐字率 / 引用不实持平、埋点命中不降 → 约束本来多余，方案落定。
- 埋点命中或等级一致性明显降 → 放开伤了追问深度，回头看是哪类约束（先加回 B3 角度上限试）。
- 回合数或成本明显涨 → 模型在空转，B1' 上限或时间信号要调。

**费用**：上次 60 场 $2.74，这次 30 场约 $1.4；先 `--limit 3` 冒烟约 $0.15。跑前探针、确认额度。不跑内部自博弈 15 场。

真机一场（约 10 回合）看状态卡与面试官行为是否自然，作为定性补充。

## 7. 明确不做（本版）

- **B7 加材料**：允许模型为简历外经历新增材料，会同时影响切段、评分、画像三处的材料模型，等 §3 有结果再议。
- **备课阶段的强制 toolChoice**（C1）：备课是回合外，且"模型不肯读包"是模型行为不是约束问题，本版不动。
- **动作集扩展**（如 `note` 只记不问、`revisit`）：切回聊过的材料用 `switch` 即可，不加新动作。
- **评分 / 汇总 / 档案的 schema**：这些是输出契约不是行为约束，与"agent 不 agent"无关。

## 8. 风险

- 模型在没有配额时可能在一个项目上问太久，时间信号是否够用要看真机与 bench 回合数。
- 角度改自由文本后，状态卡里同一角度可能被写成两种说法，记账会分裂；先按去空白全等归并，观察后再决定要不要模糊归并。
- 内部判定集删掉配额类规则后，消融数字（70% → 37%）作废，简历与 `eval.md` 要同步改，否则数字与代码不符。
