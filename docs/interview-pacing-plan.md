> 基于 [interview-flow-during.md](interview-flow-during.md)（interviewer-v6 / brief-v9）。上一轮微调见 [interview-tuning-plan.md](interview-tuning-plan.md)。

## 0. 这一场到底发生了什么

标准节奏，备课 6 个领域（5 个 technical + 1 个 project），23 个回合、22 次提问。按 trace 逐线程：

| 线程 | 领域 | 回合 | 追问层数（目标 / 上限） | 候选人回答 | 结果 |
| --- | --- | --- | --- | --- | --- |
| a5 | 多智能体编排（technical） | 1–5 | 3（2 / 3） | 66、280、1450、1489 字 | 答得好，追到上限 |
| a1 | Agent 工具调用与去重终止（technical） | 5–9 | 2 + 提示（2 / 3） | "哈希表"、2012 字、不知道 ×2 | 卡住 |
| a2 | 评测体系（technical） | 9–14 | 3 + 提示（2 / 3） | 16、4、12 字、"具体不知道"、"judge 偏了" | 备注写"答到核心一层"，信息量记满分 |
| a3 | 上下文工程与长期记忆（technical） | 14–17 | 1 + 提示（2 / 3） | "重做人工 gold"、不知道 ×2 | **线程里问的其实还是 a2 的 judge 校准** |
| a4 | RAG 失败归因（technical） | 17–19 | 1（2 / 3） | asdf ×2 | 失守 |
| p1 | Study Assistant 项目（project，目标 3 层） | 19–22 | 1 + 提示（3 / 3） | buzhidao、"都是 AI coding 做的"、不知道 | **第 19 回合的切入问题还是 a4 的 RAG 题**，项目只在第 20 回合问到一句 |

从这张表看，"过深"不是深度上限的问题（每线程最多 3 层，真实一面也是 2–3 层），而是下面六件事叠在一起：

**F1 关线程时话题没换。** 第 14、19 回合决定步都是 close_thread + open_thread，说话步却把"承接候选人刚才说的一句"写成了对上一题的再追问，把新领域的切入问题吞掉了。于是 a3 线程记录的是 judge 校准题、p1 线程记录的是 RAG 题，候选人体感"评测这一题问了八轮"，系统却以为已经换了两个领域，报告和信息量都是错的。第 14 回合的背景是 a2 已到深度上限、probe 被禁，模型不甘心，在说话步把追问偷渡了出去。

**F2 关键词回答被当成实质回答一路追到上限。** a2 的"任务完成""llm as judge"只有 4–12 字，仍然追了 3 层加提示；`answeredDepth` 只看消息 kind，不看有没有内容，这条线程的领域得分记成 1.0。真实面试官对关键词回答会追一次让你展开，第二次还是关键词就换题。

**F3 一次问两三个问题。** 追问 64–137 字，形如"比如检索、规划、写作、校验分别怎么分……分错了会带来什么问题"。决定步产出的 question 本身就是复合的，说话步的"一次只问一个问题"改不动它。候选人每题都要写小作文，这是"深"的主要体感来源。

**F4 简历项目排在最后。** 唯一的 project 领域（目标 3 层）第 19 回合才开，只问到一句就结束；前 18 个回合全是技术题。真实一面是自我介绍后直接进项目。原因：备课把项目领域排在末尾，模型按简报顺序开，代码兜底 `nextAreaToOpen` 也按简报顺序。

**F5 配比 5 技术 : 1 项目。** 简历只有一个项目，"每个项目最多一个领域"把项目压成 6 个领域里的 1 个、20 回合里的 4 个。

**F6 固定措辞（用户问的"回答硬编码"）。** 这一场有 3 个回合的话不是模型说的：第 9、17 回合（"没关系，这题我们先放一放。" + 备课时预生成的切入问题原文，一字不改）、第 22 回合的结束语。其余 20 个回合全部是模型说的，包括开场问候。代码里固定的措辞一共七条（`reducer.ts` 的 `FALLBACK_SPEECH`）：开场兜底、过渡、结束语、跳过、卡住第二次、提示兜底、"我再说一遍"前缀；前四条只在候选人插话（跳过 / 再说一遍 / 结束 / 卡住第二次）或模型失败时用。另外每个领域的切入问题是备课时预生成的，面试中模型"可改写措辞、不改内容"，第 1、5 回合模型改写并锚到了自我介绍上，第 9、17 回合走固定分支就原样播出来。

## 0.1 网上大厂一面的流程对照

能抓到的公开面经（2025–2026，Agent / 大模型应用岗）：

- 结构基本一致：自我介绍 1–2 分钟 → **项目深挖是最大的一块** → 八股 / 基础 → 一道场景题 → 一道算法 → 反问；一面 45–60 分钟。牛客一篇小红书 AI Agent 一面记了 28 问：自我介绍 1、项目 11、Agent 八股 10、Redis / JVM 基础 3、场景题 1、反问。另一篇一面"自我介绍自然过渡到项目，聊了半小时，再问基础和算法"。
- 追问方式：项目上追"你自己做的哪部分、怎么量、为什么这么选"，2–3 层；八股题 1–2 层，答不上就换下一题，不会连给两次台阶；字节三面面经里"一面二面考广度，三面才追着一个问题不放"，开放题答不上时面试官给引导。
- 问法：一句话一个问题；场景题先铺一句场景再问一个点。
- 阿里有一种变体：不自我介绍，直接给场景（设计智能客服 Agent）连续追问，再 5 道系统设计题。这是二面 / 三面的风格，不是一面默认。

对照当前系统：深度目标 2、上限 3 与真实一致；差在项目的位置和占比（F4、F5）、问法（F3）、对关键词回答的处理（F2），以及 F1 这个 bug 让人感觉一题问了八轮。

## 1. 关线程就是关线程（F1）

### 现状
说话提示的通用规则"最多一句话承接候选人刚才说的（也可以没有），然后把问题问出来"对 close_thread + open_thread 同样生效；`nextLine` 只说"自然过渡到下一领域，把这个切入问题问出来"。模型把"承接"写成再追一问，切入问题被丢掉。代码不校验说出来的话与决定是否一致。

### 改动
- `buildSpeakPrompt` 的 close_thread 分支单独写指令：上一段已经结束，不要再就它提任何问题、不要点评；一句过渡（可以没有），然后问下一领域的切入问题；说出来的话里只能有这一个问题。`respond` 那段通用规则不再拼进这个分支。
- 原本不打算做代码层校验（说话是自由文本，怕误伤改写）；真机第一场发现卡住换题时模型仍会"换个场景"继续问上一题，于是加了一道宽松的守门：换题的话与下一领域切入问题的 3 元字符组覆盖率不到 0.3 才替换成固定过渡 + 简报原句（改写照常通过），见 §9。`describeAction` 没有改，说话提示的关线程分支已经足够。

### 验收
真机一场：每条 `question(open_thread)` 消息问的就是该线程领域的切入问题（可改写）；trace 里没有线程的切入问题属于别的领域。

## 2. 关键词回答追一次就够（F2）

### 现状
候选人回答只有关键词时，模型照样按阶梯往下追到上限；`answeredDepth` 按消息 kind 计数，关键词回答算实质回答，领域得分记满。硬门 `probeBeforeClose` 在深度不到目标时拒一次关线程，进一步把模型往"追"推。

### 改动
- 决定提示加一条规则：候选人只给关键词、不展开时，追一次让他展开；第二次还是关键词或空话，就 close_thread、note 写清"只给了关键词"，不要追到上限。
- `close_thread` 加 `verdict` 字段（answered / thin / failed，模型的判断）：answered 是有实质回答，thin 是只有关键词或空泛，failed 是一句没答上。`areaScore` 用它：failed 记 0，thin 减半，answered 照旧按层数。这样信息量用的是面试官的判断，不用字数阈值。`probeBeforeClose` 在 verdict ≠ answered 时不拒。
- trace 与复盘页把 verdict 显示在线程摘要里；`THREAD_NOTES.stuck` 这类系统 note 对应 verdict=failed，不再靠 note 文案判断。

### 验收
真机一场里故意只答关键词：同一线程最多一次"展开说说"，第二次就换题；信息量面板上这条线程不是满分。

## 3. 一次只问一个问题（F3）

### 现状
`probe` / `open_thread` 的 question 由决定步写，经常并列两三个子问题；说话步的"一次只问一个问题"只能改措辞。

### 改动
- 决定工具的 question 描述改为：一句话一个问题，一个问号；不要"A、B、C 分别怎么"并列子问题；要引场景就先铺一句场景，问的点只有一个。
- 决定工具层软门（与 anchor 校验同一套重试机制）：question 里超过一个问号或含"分别"并列结构时拒一次，理由"一次只问一个问题，把最想问的那个留下"；第二次照常接受并记录。不设字数上限、不截断。

### 验收
真机一场：追问与切入问题绝大多数只有一个问号；面试官每条消息字数 p50 比这一场（约 80 字）明显低。

## 4. 项目先行、项目占比（F4、F5）

### 现状
备课模型给的领域顺序技术在前、项目在后，代码兜底按简报顺序开领域；"每个项目最多一个领域"，简历只有一个项目时项目占 1/6。

### 改动
- 备课后代码把 project 领域排到最前（技术领域相对顺序不变）；决定提示加"自我介绍之后先进简历项目，技术题放在项目之后；候选人自我介绍里点到的方向可以顺势先切"。
- 项目占比二选一（见 §7 待定）：
  - A. 简历项目少于 2 个时，允许同一个项目开两个领域（不同模块 / 不同决策，projectId 相同）；备课提示相应放宽。
  - B. 项目领域的深度上限从 3 提到 4（`MAX_AREA_DEPTH` 按 kind 区分），领域数不变。
  推荐 A：两条线程两个切入点，比一条线程追 4 层更像真实面试的"这个项目里你还做了什么"。

### 验收
真机一场：第一条线程是项目；项目线程回合数占总回合 30% 以上。

## 5. 卡住换题与结束语交给模型说（F6）

### 现状
候选人卡住第二次：代码固定"没关系，这题我们先放一放。"再拼上备课切入问题原文；面试结束：固定结束语。省的是一次说话调用（约 5k 输入 / 60 输出 token）。

### 改动
- 这两个分支从 `fixed` 改成 `forced`（与开场、提示同一条路）：动作由代码定，模型只写话。卡住换题：一句放下这题、然后问下一领域的切入问题（受 §1 的规则）；结束：一句告别，告知稍后有报告。
- `FALLBACK_SPEECH` 里 `stuck` / `transition` / `closeInterview` 只在模型失败时用；跳过、再说一遍、结束请求仍固定（候选人明确要求的操作，不需要面试官措辞）。

### 验收
真机一场：连说两次"不知道"后，面试官的话不是那句固定文案，切入问题也不是备课原文照播。

## 6. 顺手做 / 不做

- 提示（hint）经常写成缩小范围的新问题（"先说一个维度：……？"），真实面试官也这么做，不改。
- 不做反问环节（已定）。
- 快速 / 深入节奏的领域数与深度不动；这一场的问题在标准节奏下也不是数字问题。

### 9.2 真机（字节 豆包 Agent 开发 JD，标准节奏，gpt-5.4-mini，本地 3000）

第一场（12 回合，脚本作答）：备课 2 个项目领域 + 3 技术 + 1 行为，项目领域排在最前，第 1 回合就进了简历项目；11 次提问全部一个问号一个问题（p50 44 字，上一场约 80 字）；"哈希表"追了一次、"去重"第二次就关线程（verdict=thin，报告页标"只有关键词"，领域得分减半）；模型自己关线程开新领域时说的就是新领域的切入问题（第 5 回合）。暴露一个问题：卡住第二次换题（第 7 回合）模型把"放下这题"写成"那换个场景……"继续问日历题，下一领域的切入问题被吞——于是加了 §1 的代码守门并收紧 stuck 的说话指令。

第二场（7 回合，只验证卡住换题）：两次"不知道"后面试官直接问下一领域的切入问题（第 3、5 回合），两次都是模型自己说对了，守门没有触发；线程记 verdict=failed、状态 skipped。

顺带发现：你之前自己启的 dev 服务器内存里是旧的 Prisma 客户端，加列后回合落库报 `Unknown argument verdict`，重启即好；这次验证用的两场和两场落库失败的废会话都已删除。

## 10. 第二轮观察（2026-09-13，用户真机一场：会话 `cmtzx11i50001wstak53kqmce`，标准节奏，interviewer-v7 / brief-v10）

19 回合、18 次提问。备课 4 个领域：a1 项目（主循环与终止控制，目标 3）、a4 项目（多智能体仿真评估，目标 3）、a5 技术（工具调用与上下文工程，目标 3）、a6 技术（评估体系，目标 2）。线程：a1 追 4 层后候选人跳过；a4 追 4 层，verdict=answered；a5 追 3 层，answered；a6 追 2 层，两次点"提示"后关线程 → 领域用尽 → 结束。

上一轮的五步都生效了：项目排第一、第 1 回合就进项目；18 次提问全部一问一个问号，p50 约 55 字（上一场约 80）；关线程开新领域时说的都是新领域的切入问题；提示只有 32 字；结束语是模型说的。

新暴露的三件事：

**G1 两次"提示"就结束：是真结束，按设计走的，但设计有两个漏洞。** 第二次点"提示"按"卡住第二次"关线程（verdict=failed），代码接着找下一个领域，4 个领域都考察过了，`fallbackAction` 只剩 close_interview（"所有领域已考察"）。漏洞一：第一次提示之后候选人还没答，第二次点的"提示"应该是"还是不会"，但也可能是"再具体一点"，现在一律当卡住；漏洞二：标准节奏备课只给了 4 个领域（minAreas 的下限），单项目双领域各 4 回合把预算吃掉一半，一个线程提前跳过就没有储备领域可换，18 问就结束了。

**G2 四个领域实际只有两个话题。** a1（项目：重复调用检测与终止）和 a5（技术：工具调用校验失败的 observation 结构）是同一个话题从两边问，a4（项目：仿真评估）和 a6（技术：评测体系）也是。同一话题连问 8–10 次，加上每线程 4 层（目标 3 + 松弛 1），就是"过细"的体感：a1 第 4、5 问已经到了 `state_revision` 怎么算、第 4 次重试之后终止还是升级这种粒度。单问题本身都合格（锚在原话、一问一点、项目题问"怎么落地"），问题在组合：技术领域重复了项目领域的考点，而且项目线程可以追到 4 层。

**G3 同一 JD 每次问的差不多。** 备课的输入每次一样（JD、简历、同一个技能包、同一提示词），gpt-5.4-mini 在同样输入下会收敛到同一批场景：日历改期（"把下周三下午的会议改到周五"）在两场里都出现了，"线上变好离线没变好你先怀疑什么"也是。备课拿到的历史只有上几场的失守点（recentWeaknesses），没有上几场问过什么。技能包里没有这些例句，是模型自己的惯性。

### 10.1 建议改动

1. **技术领域避开项目领域的考点（G2）。** 备课规则加一条：technical 领域不得与 project 领域覆盖同一考点（项目线程已经在考它），技术题从 JD 与技能包里挑项目没覆盖的方向。代码层不校验，靠提示。
2. **线程上限回到 3 层（G2）。** `MAX_AREA_DEPTH` 4 → 3：目标 3 的线程不再有松弛（最多 3 层 4 问），目标 1–2 的仍可多追一层。评测指标同一常量，一起变。
3. **备课多给一个储备领域（G1 漏洞二）。** 标准节奏 minAreas 4 → 5，装箱时储备领域 depth 1；被跳过或失守的线程释放的预算由它接住。快速节奏不动（13 回合装不下）。
4. **第二次"提示"不当卡住（G1 漏洞一）。** 提示之后候选人再点提示，按"再说一遍上一条提示 + 换个问法"由模型处理一次（forced，task=hint，线程 `hinted` 已为 true 时改为收窄问题），第三次才关线程。这一条会多一次说话调用；也可以不做，只在房间里把第二次的按钮文案改成"还是不会，换一题"让候选人知道后果。倾向后者：真实面试官不会给两次台阶，把后果说清楚就够了。
5. **备课带上上几场问过的领域与切入问题（G3）。** `buildMockInterviewContext` 已经按岗位名取了最近 5 场的题目，多带一份 `recentQuestions`（领域名 + 切入问题，最多 10 条）进备课载荷，规则："这些是最近几场同岗位问过的，换场景、换切入点，不要再问同一件事。"这是真实面试官换人换题的等价物。
