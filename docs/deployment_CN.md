# 部署指南

[English](deployment.md) · [返回 README](../README_CN.md)

## 运行模式与数据

| | 本地部署 | 网页版（`APP_MODE=trial`） |
| --- | --- | --- |
| 工作台 | 运行 OfferCome 的机器上的 SQLite 与文件 | 浏览器存储；清除站点数据会删除本地副本 |
| 简历原件 | 本地文件系统 | 浏览器 IndexedDB；上传内容由服务端解析 |
| 模型配置 | 保存在本地应用中 | 保存在浏览器，默认记住，也可仅在本次会话保留 |
| AI 请求 | 发送给你配置的模型服务 | 配置与任务输入经服务端发送给你配置的模型服务 |
| Boss 同步、语音作答、面试材料导入、联网搜索 | 支持 | 不支持 |

网页版从空工作台开始。接口会处理请求数据，但不将工作记录、上传文件或模型密钥保存到服务端数据库或文件中。浏览器存储不会跨设备同步。AI 任务所需的输入仍会发送给模型服务，因此“浏览器保存数据”不代表所有处理都在设备内完成。

本地版的文本理解与语音转写可分别配置服务商，支持 OpenAI 兼容接口和本地模型。使用相应 AI 功能前，请先在**设置**页完成配置。

## Boss 直聘同步

请在安装 Chrome 或 Edge 的桌面环境中从源码运行。标准 Docker 配置无法在宿主机桌面打开浏览器窗口。

```powershell
npm run boss:login
npm run boss:sync -- --dry-run
npm run boss:sync
```

登录、扫码、验证码和安全校验由你本人完成。同步只读取已有投递记录，不会代你投递或发送消息。

- 记录会去重，已删除的岗位不会再次导入。
- 同步时，仍处于“已投递”且已有 30 天未记录到互动的岗位可能被标为“已拒绝”；已有记录的其他阶段会保留。
- 判断优先使用来源中的最后互动时间，缺失时使用投递时间或首次发现时间。首次导入的旧记录也可能被标为拒绝。
- 该规则在同步时执行，没有独立定时器。可先运行 dry-run 查看拟变更内容。

## Docker 存储与维护

仓库的 [Compose 配置](../docker-compose.yml) 挂载了：

- `offercome-data` → `/data`，用于 SQLite。
- `offercome-local` → `/app/.local`，用于上传文件及其他本地状态。

查看日志或停止应用：

```bash
docker compose logs -f offercome
docker compose down
```

停止应用会保留数据卷。**`docker compose down -v` 会永久删除它们。** 删除或替换存储数据前，应备份两个数据卷。

## 托管要求

完整本地版需要持久化数据库与文件存储、Node.js 运行环境和长任务支持。音频导入可能依赖 ffmpeg，模拟面试生成和画像刷新会运行后台任务。

将这一模式迁移到 serverless 平台，需要处理函数超时、请求体大小限制、后台任务执行与持久化存储。网页版通过浏览器存储和无状态接口避免服务端持久化，但 AI 请求仍受托管平台的时长和大小限制。

Vercel 在没有显式覆盖时默认使用网页版模式。仅修改模式标记，不会自动补齐完整本地版所需的运行条件。
