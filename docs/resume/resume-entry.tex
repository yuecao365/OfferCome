{OfferCome：个性化模拟面试 Agent}
{2026年7月 -- 2026年9月}
\resumeProjectSubline{自研 Agent runtime、多 Agent 分工、三层 Memory、动作层工具调用控制、事件溯源与面试官黑盒基准}
\resumeProjectGithub{https://github.com/yuecao365/OfferCome}
\resumeItemListStart
\resumeItem{\textbf{自研统一 Agent runtime}：结构化输出三级容错（按 schema 解析 $\to$ 回传校验错误重试 $\to$ 调用方兜底）、工具放行 / 记账 / 需确认三档权限、步数--token--时长--成本四维限额、按前缀缓存组织消息（面试官回合命中约 80\%）；1636 次真实调用一次通过率 \textbf{78.6\%}，容错后可用率 \textbf{97.0\%}。}
\resumeItem{\textbf{多 Agent 分工}：备课 Agent 从 JD 与简历产出能力蓝图和待核实的说法，面试官 Agent 围绕它们追问，评分与总结 Agent 用不同模型独立打分；Agent 间只通过事件日志和结构化产物交接。}
\resumeItem{\textbf{三层 Memory}：场内面试官逐回合维护笔记，记录各说法验证状态，待验证项清空即收尾，不按时间或轮数截断，主动收尾比例由 \textbf{0.25} 升至 \textbf{0.53}；跨场沉淀每场的验证结果与反复出现的短板；长期由各场评分累积成能力画像。}
\resumeItem{\textbf{动作层工具调用控制}：面试官每回合先给出结构化决策（追问 / 换题 / 澄清 / 收尾及目标）再生成话术，代码按会话状态校验，不合法则带原因退回重出，再不合法由代码定动作、模型只负责措辞；控制发生在执行前而非文本事后过滤，提示注入无法改变面试进程。}
\resumeItem{\textbf{事件溯源}：会话只保存只追加的事件日志，进度、状态卡、评分切段都从它实时计算；任一回合可用历史日志重放，改提示词后可对旧面试离线回归。}
\resumeItem{\textbf{InterviewBench 黑盒基准}：任何面试官实现按同一接口提交，只凭逐字稿和评分卡打分；与同一模型仅用一段提示词直接面试的基线相比，本系统评分卡\textbf{引用不实每场 0.10 vs 0.53}、\textbf{一段多问率 0.24 vs 0.65}。}
\resumeItemListEnd
