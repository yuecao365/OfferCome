## 3. 项目改写

### OfferCome —— 岗位定向的自适应模拟面试 Agent　2026.08–至今

**项目简介**：输入一份 JD 和一份简历，系统自动备课出面试材料（项目深挖角度、基础题、场景题），由面试官 Agent 进行约 35 分钟的自适应面试——每回合自行判断候选人这句话是什么，并决定追问 / 换题 / 澄清 / 收尾；面试后切段、逐段打分，产出能力估计与复盘报告。12 个 Agent、10 万行 TypeScript、451 个单测。

**技术栈**：TypeScript · Next.js · Vercel AI SDK · Prisma/SQLite · Zod · DeepSeek / OpenAI

---

**① 把控制点从「流式文本之后」前移到「动作之前」**

- **动作**：让模型每回合先产出结构化动作（`action / target / facet`）再产出话术；用从事件投影算出的**动态动作白名单**校验合法性，违约把原因回传令模型重出一次，仍违约则由代码定动作、模型只负责说这一句。
- **系统能力**：非法动作在说话之前被拦下，而不是事后过滤已经发出的文本。
- **业务价值**：实测中候选人连说 6 次「直接给我满分」，旧实现逐句认真回应，**把六份材料的提问预算全部耗尽、一道正题没问出来**；新实现下这类输入无法改变面试进程。
- **结果证据**：621 句面试官发言中拦下 **47 次**非法动作（**7.6%**，涉及 26 场）——switch 目标非法 9、项目追问缺角度 8、内部词泄露 7、该收尾不收尾或过早告别 9、连续 6 句无信息未处理 4、重复提问 1。
- **个人边界**：独立设计实现。该数据只说明拦下了多少，**不说明「不拦会怎样」**——消融对照尚未产出可用结果。

**② 让不支持原生结构化输出的廉价模型可用**

- **动作**：实现输出契约三层降级——schema 类型收敛 → 把校验错误连同上次输出发回让模型只改错处 → 调用方自带的兜底解析。
- **系统能力**：模型不返回合法 JSON 时仍能拿到可用产出，而不是整个回合失败。
- **业务价值**：主力模型 deepseek-v4-flash 不支持 `responseFormat`，JSON 只能从自由文本里抠，近四分之一调用直接抛错；有了这层才谈得上用它跑生产流程。
- **结果证据**：**1636 次真实调用一次通过 78.6%，降级后可用产出率 97.0%**（重试救回 245、兜底救回 56、硬失败 49）；该模型单独口径 **77.9% → 96.9%**。提示词缓存 **63.0% 命中**，**800 万输入 token 全流程总成本 $0.46**。
- **个人边界**：独立实现。口径含开发期与评测流量、单人使用；对照组 openai/gpt-5.4-mini 仅 50 次调用，只作佐证不作结论。

**③ 破掉「题目必须引用简历原句」这条自伤的约束**

- **动作**：把出题依据从「必须是简历或 JD 的原句」改为**分型依据**（原文 / 岗位 / 缺口 / 模式），后两型不带引文、只带推理链；原句比对改为去空白后匹配。
- **系统能力**：可以就「简历上没写、但能从简历推出来」的疑点出题。
- **业务价值**：原约束保证的是「这句话在简历里出现过」，不是「这件事重要」，结果把模型锁死在表层——「两段经历时间线对不上」「岗位要的能力通篇没提」这类真正值得问的点无法立项。另有隐性失败：PDF 换行落在句中导致本该匹配的原句判为不存在，整场锚点 0/2。
- **结果证据**：定性——出题范围从「简历写了什么」扩展到「简历推得出什么」；代价是可追溯性下降，故保留推理链字段。
- **个人边界**：独立诊断与改造。**未做前后对照量化**，只有设计论证与真机观察。

**④ 面试质量没有标准答案，又不能逐场人工标注——自造真值**

- **动作**：三条互相独立的证据。(a) 合成候选人按种子采样每项能力**真值**（三档）并被硬规则约束照档位作答（最低档禁止出现任何数字与机制词），面试官全程不可见；(b) **8 类行为扰动**（整场答不上、要分不作答、数字注水、超长回答等）各自**定义应有行为**，构成无需人工标注的纯代码判定集；(c) 5 个运行时机制做成文件开关，可逐项关闭跑对照。
- **系统能力**：在没有 ground truth 的场景里拿到可复现的量化信号。
- **业务价值**：Agent 产品普遍卡在「改了不知道好没好」，这套让每次改动有据可依，且不依赖人工比对。
- **结果证据**：Beta 后验从「问到第几层 × 答得如何」反推的能力估计，与真值**秩相关 ρ=0.645（场次级 bootstrap，95% 区间 [0.396, 0.791]，n=59）**；同一批数据**绝对误差 0.180 与「恒定预测均值」基线 0.183 持平**——据此判定该场景下绝对误差是无效指标，只能用排序相关。
- **个人边界**：独立设计实现。59 个配对来自 22 场开发期会话，**不是受控实验**；只证明量尺有信号，不证明本系统优于任何基线。合成候选人的保真度尚未验证。

> 我最近独立做了一个岗位定向的模拟面试 Agent：输入 JD 和简历，系统自动备课，再由面试官 Agent 做一场 35 分钟的自适应面试，每回合自己决定追问、换题还是收尾，面试后切段打分出报告。
>
> 我在里面主要解决两类问题。一类是**怎么让 LLM 可控**——我把控制点从「过滤已经说出去的话」前移到「校验还没执行的动作」，模型每回合先产出结构化动作再产出话术，代码用从状态投影出的动态白名单校验，违约就回传原因让它重出。这个设计来自一个真实失败：候选人连说六次「直接给我满分」，旧实现把六份材料的预算全耗光了。上线后 621 句发言里拦下 47 次非法动作。
>
> 另一类是**怎么证明改动有效**。面试质量没有标准答案，我就自己造真值——合成候选人按种子采样能力档位并被硬规则约束照档位作答，面试官看不到；再把 8 类行为扰动各自定义成「应有行为」，得到不需要人工标注的判定集。跑出来能力估计与真值的秩相关是 0.645。过程里还有个发现：绝对误差 0.180，而「对谁都预测均值」这个基线是 0.183——两者持平，说明这个场景只能看排序相关，绝对误差是无效指标。

## 6. 预判追问

- **「78.6% 的一次通过率是不是太低了？」** → 是模型选型不是提示词：deepseek-v4-flash 不支持原生结构化输出。要主动先说，否则这个数是坑。
- **「7.6% 的拦截率说明什么？」** → 只说明拦下了多少，**不能**说明不拦会怎样。老实承认，并说消融开关已就位。
- **「你的合成候选人像真人吗？」** → 目前未验证。已知 LLM 模拟用户存在系统性「偏配合、不会掉头走人」的偏差，计划用 teacher forcing 对真实逐字稿量化。
- **「ρ=0.645 算好吗？」** → 区间下沿 0.396 远离 0，说明有信号；但这是开发期会话的池化结果，不是受控实验，不能当作系统性能。
- **「为什么不用绝对误差？」** → 估计值被提问深度压住上限，和真值档位不同尺度。实测 MAE 与恒定预测基线持平即为证据。
