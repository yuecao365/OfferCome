# 面试设计修订 v4：定制出题、说话可靠、面试官的自主与记忆（2026-09-18 草案，待放行）

> 来源：用户 2026-09-18 压力实测（字节跳动 · AI 工程开发实习生-剪映，`cmu7eo11t000138tasfsvy5or`）与前一场美团。三条反馈：① 基础题只是技能包里的好题原样出，不贴 JD 和简历；② 面试官说了一段又撤回、重复、说到一半断掉；③ 感觉是代码驱动不是 agent，记忆与上下文糟糕。下面每条先给证据，再给方案。上一篇：[interview-design-revision-3.md](interview-design-revision-3.md)。

## 1. 证据

### 1.1 基础题就是技能包的好题

两场 8 道基础题与技能包"好题示例"的相似度：1.00、0.89、0.85、0.78、0.77、0.71、0.68、0.65。备课提示词把每个主题的"好题示例"原文喂给模型，模型照抄是最省力的做法。另外剪映 AI 实习生被问了"Full GC 停顿 3 秒看哪几个数字"（backend-java 栈包），跟岗位无关——栈包按简历里出现的语言选，AI 岗不该带语言栈的八股。

### 1.2 撤回、重复、说一半

三种现象三个原因，都在记账里：

- **撤回**：模型在第 57、63 回合两次想收尾（"感谢你参加这轮面试，后续结果会由招聘同学同步"），代码判"过早告别"（配额里场景题还没聊），把已经流给用户的话换成固定句"这个我们先放一放，换个话题，说说另一段经历"。用户看到的就是说完又撤。**模型的判断是对的**：候选人已经连续六次"不知道"，该收尾了；代码的规则（配额没聊完不许收）是错的。
- **重复**：那句固定换题句连续出现两次（第 57、63 回合一字不差），因为要换的材料（s1）已经在问了，`areaToAsk` 找不到下一份就用固定句兜底。
- **说一半**：第 41 回合"那换一道，讲思路就行。用户反馈"、第 49 回合"你觉得这个"戛然而止，finishReason 是 stop。原始输出的尾巴是 `<｜DSML｜ invoke name="load_skill">…`：DeepSeek 在 JSON 模式的流式输出里想调工具，把工具调用写成了 DSML 文本塞进 say 里，say 的 JSON 到那里就断了。流式解析拿到半句话就发给了用户。两场各出现一次，都在换到基础题、现场卡写"先查技能包"的那一回合。这是 DeepSeek + 流式 JSON + 工具三者叠加的服务商问题，探针里非流式的 generateText 调工具是正常的。

### 1.3 "不像 agent，记忆糟糕"

- 候选人从第 22 回合起连续六次"不知道 / 不清楚"，代码仍按配额把四份材料一份份问完（每份答疑一次、换下一份），第 69 回合还在"最后几分钟，不聊项目了，假设你手上就一个推理服务……"。面试官没有权力说"今天就到这"。
- 笔记 300 字整份重写，第 12、64 回合模型写了空笔记；历史只追加不裁（这场没超上限），但模型看不到"这个人前面已经说过什么"的结构化记录，回应里很少接候选人上一句的原话。
- 现场卡是命令式的："换到 q1，用它的切入问法起头"。模型只有一个判断（讲透了没有）。这是 v3 的设计选择（判断归代码），压力场景下它的代价显出来了：候选人越不配合，代码越显得机械。

## 2. 方案（三段，各自一个提交）

### A. 备课：题必须贴 JD 或简历，技能包改成"怎么出题"而不是"题库"

1. **备课提示词不再喂"好题示例"原文**。每个主题只给阶梯、期望信号、危险信号，加一条硬要求：每道题写出锚点 `anchor: { kind: "resume" | "jd", text: 逐字引用 }`——从简历里他用过的东西或 JD 里团队的系统出发问原理、边界或排查；没有锚点的题不要。
2. **代码校验**：备课产出的每道基础题与全部技能包好题算相似度，≥ 0.6 的判为照抄，连同锚点缺失的一起退回让模型重写一次（只重写这几道，不重跑整份简报）；仍不合格的保留但在 trace 里标"照抄"，指标"基础题照抄率"进模拟器表。
3. **栈包只在 JD 点名语言时才进题池**；AI / agent 领域包当主包时，基础题名额全给领域包与计算机基础。
4. **技能包重写**：主题段从"阶梯 / 好题 / 危险信号 / 期望信号"改成"阶梯 / **出题锚点**（简历出现什么就从哪切、JD 出现什么就从哪切） / 危险信号 / 期望信号"；"好题 / 坏题对比"段保留但只作风格示范，明确写"不要照抄"。先改这个用户会碰到的五个包：ai-llm、agent-harness、backend、cs-fundamentals、project-deep-dive；其余包由脚本把"好题"字段改名为"风格示例"、加"出题锚点"占位，后续按需补。
5. 验证：备课单测 + 两场冒烟看照抄率（目标 ≤ 1/4）与题是否带锚点。

### B. 面试官回合：说出口之前先过底线；工具走协议通道

1. **面试官改跑 runAgent 循环，不再流式**。工具调用走协议字段（DeepSeek 在非流式下正常），底线在说出前执行，用户永远看不到被否决的话；DSML 截断消失。前端保留打字机效果（收到整句后逐字显示），首字延迟从约 0.5 秒变成 2–4 秒——这是唯一代价，我认为值。G1 里"流式回合是刻意例外"的说法随之删除，面试官和其它 agent 完全同构。
2. **允许面试官提前收尾**：决策加一条——候选人连续 4 句没有信息（答不上 / 不是我做的 / 不作答，跨材料计）就允许 closing；模型标了 closing 且允许，直接告别。固定换题句删掉：找不到下一份材料就收尾，不再"说说另一段经历"。
3. **失败清单**：1.2 的三条各进一行，扰动 `dont_know` 延长到整场（连续不知道）复现收尾逻辑。

### C. 面试官的自主与记忆

1. **决策权重分**：代码只守硬约束（每份材料的追问上限、不重复、不泄露内部词、没枯竭不许告别），**下一步问什么由模型提**：现场卡列出可选项（接着追当前角度 / 换角度 X / 换材料 Y / 答疑 / 收尾）与每项的余额，模型输出 `move` 与一句理由，代码只在违约时否决并改问。这是从"命令"改成"约束 + 选项"，模型的每个意图仍可否决，但正常情况下它在做决定。
2. **工作记忆结构化**：笔记从 300 字自由文本改成固定段落（每份材料一段：问了什么、答到哪、存疑；候选人整体一段：风格、可信度），上限 800 字，模型只改本回合涉及的段（代码合并），空笔记不再覆盖旧笔记。
3. **接话**：输出加 `ack`（≤ 30 字，对候选人上一句的回应，可空），say 之前先说它；代码校验 ack 不含问号。让候选人感到被听到。
4. **历史**：前 20 回合不裁；超过才按块裁。
5. 验证：`needy` / `dont_know` / `manipulate` 扰动各一场 + 一场正常，看指标"模型提议被否决的比例"（新增）、"一句多问"、缓存命中率不退。

## 3. 顺序与费用

建议 **B → A → C**：B 最便宜、直接消灭三种可见故障；A 决定题目质量；C 改的是控制哲学，放最后，因为 B 做完面试官跑在循环上，C 的改动才顺手。每段冒烟 2–3 场（约 0.4 美元），A 段技能包重写不花模型费用。

## 4. 不做的

- 不换服务商来绕 DeepSeek 的 DSML 问题：非流式循环本身就解决了，且其它服务商也可能有各自的问题，运行时层解决才是对的。
- 不把决策整个交给模型（C.1 保留硬约束）：F1 / F2 两次材料自报误报的代价还在，否决机制是这个项目最有辨识度的设计。
