# 对话式面试官 Agent 方案（v2：从真实面试出发）

2026-09-07。v1 把"对话"理解成"用聊天窗口把 8 道预生成的题问完"，仍是脚本执行器。v2 从真实面试怎么进行出发重新推导，不以现有代码为约束；现有模块能复用的复用，不能的删。

---

## 0. 真实面试是怎么进行的

以一场 45 分钟的技术一面为例，面试官实际在做的事：

1. **备课（面试前 5 分钟）**：翻简历，圈出 2–3 个要深挖的点（写了数字的成果、只写框架名的经历、时间线的空洞）；心里有一张"这个岗位必须考察的领域"清单和大致的时间分配；手边有自己常用的题和追问套路。**没有固定的题目清单。**
2. **开场**：简短介绍，让候选人自我介绍。自我介绍决定从哪里切入。
3. **项目深挖（核心，20–30 分钟）**：挑一个项目，"你负责哪部分"→"为什么这么设计"→"还考虑过什么方案"→"出过什么问题、怎么定位"→"数字怎么来的"→"如果 X 变了你会怎么改"。每一句追问都由上一句回答决定。面试官在脑子里形成假设（"这人只用过框架，不懂原理"）并用问题去验证。答得好就继续往下挖；明显卡住时给一次台阶，再卡就换话题。
4. **基础与原理（10–15 分钟）**：从项目里牵出的技术点或岗位要求出发，按"概念 → 原理 → 场景排查 → 权衡"的阶梯往下问，在候选人失守的那一级停下。
5. **收尾**：候选人提问，结束。
6. **面试后**：对照几个维度（基础、项目深度、沟通、潜力）写评价并给结论。**评价发生在面试之后，依据的是整场对话，而不是逐题打分。**

从中提炼面试官这个"agent"的本质属性：

| 属性 | 含义 |
|---|---|
| 目标驱动 | 手里是"要覆盖的领域 + 要验证的假设"，不是题目清单 |
| 工作记忆 | 随时记着：已经确认什么、存疑什么、失守在哪里、还剩多少时间 |
| 自适应深度 | 答得好继续挖，失守即停，救场最多一次 |
| 时间盒 | 每个领域有预算，会主动切段 |
| 评价与提问分离 | 面试中只记笔记，打分在面试后按固定标准做 |
| 专业知识 | 知道该领域怎么考、什么是好回答 |

## 1. 映射为 agent

三个阶段、一个状态、一组工具、一套代码守的规则。

### 1.1 备课阶段：生成面试简报（替代"生成 8 道题"）

输入岗位与简历，输出 **Interview Brief**：

- **考察领域**（3–5 个）：来自现有的岗位蓝图（能力项），每个领域带时间配额和**领域评分表**（1–5 级带行为锚点）。评分表在面试前固定，是公平性的锚点（见 §3）。
- **简历假设**（3–5 条）：要验证的具体点，每条引用简历原文（逐字硬门沿用）。如"简历称 prompt 长度降低约 50%，验证其度量方法与基线"。
- **每个领域的切入问题与深度阶梯**：切入问题一道即可，阶梯来自技能包（技能包正是"面试官的专业知识"）。
- **时长与轮次**：用户选 15 / 30 / 45 分钟与轮次；题目数量不再是输入，它是面试过程的结果。

现有出题链的裁决器（引用真实性、配额、去重）大部分作废；蓝图、技能包、证据逐字检查、技能包选择器保留。

### 1.2 面试阶段：面试官回合

候选人每条消息触发一个回合。回合输入：简报、**工作记忆**（见 1.3）、最近若干回合原文、当前线程状态、预算。回合输出：一条要说的话（流式）+ 至多一个动作 + 对工作记忆的增量更新。

**动作（工具）**

| 动作 | 真实面试里对应 | 代码守的规则 |
|---|---|---|
| `probe(question)` | 顺着回答往下追 | 当前线程深度 ≤ 阶梯上限（默认 4）；不得含评分表与期望信号原文 |
| `rescue(hint)` | 给一次台阶 | 每线程 ≤ 1 次 |
| `open_thread(areaId, question)` | 切到一个新领域/新项目 | 该领域尚有时间配额；一次只能有一个线程进行中 |
| `close_thread(verdictNote)` | 这一段问够了 | 触发该线程落库（见 §4） |
| `ask_intro()` | 请自我介绍 | 只能在开场 |
| `close_interview()` | 收尾 | 仅当所有领域达到最低覆盖，或时间用尽，或候选人要求 |
| `lookup_resume(section)` | 翻简历 | 只读 |
| `load_skill(name)` | 翻自己的题库 | 复用现有工具 |

候选人插话由代码先识别再交给模型：说"跳过"→ 强制 `close_thread`（标记跳过）；"提示"→ 若预算允许则 `rescue`，否则面试官说明并推进；"再说一遍"→ 重复上一问；"结束"→ `close_interview`。

**不变量（代码持有）**
1. 同一时刻至多一个线程进行中。
2. 每个领域至少一个线程；每个线程至少一个候选人回答（否则视为跳过）。
3. 连续 2 个回合无动作 → 代码按简报顺序强制 `open_thread` 或 `close_thread`。
4. 回合失败 / 超时 / 无法解析 → 用简报里下一领域的切入问题原文直接问，不中断。
5. 时间预算：按回合数折算（默认 1 回合 ≈ 1.5 分钟），领域配额用尽时代码拒绝再 `probe`，只允许 `close_thread`。

### 1.3 工作记忆（scratchpad）

面试官的"脑子"，每回合由模型增量更新，代码持久化：

```
established: [{ areaId, claim, evidenceTurnIds }]   // 已确认的能力点
doubtful:    [{ areaId, claim, why }]               // 存疑，待验证
failed:      [{ areaId, rung, turnId }]             // 失守的阶梯位置
hypotheses:  [{ id, text, status: open|confirmed|refuted }]  // 来自简报的简历假设
```

作用：一是让追问有依据（模型看到"存疑：是否真的做过压测"就会去问）；二是让面试后的评价有据可查；三是控制上下文——远处的对话原文可以被裁掉，记忆保留结论。报告页可以把它作为"面试官当时的判断"展示给用户，这是学习价值最高的部分。

### 1.4 面试后阶段：评价（替代逐题评分）

- **分段**：代码按线程把对话切段（每段 = 切入问题 + 追问 + 候选人的全部回答），确定性的，不靠模型。
- **按领域评分**：复用现有逐题评分 agent，输入改为"该领域的评分表 + 该领域所有线程的对话段 + 工作记忆里的相关条目"，输出各锚点维度分与证据句（证据句逐字来自候选人回答，硬门沿用）。
- **总结与行动计划**：复用现有总结 agent，输入改为领域分与笔记。
- **画像**：线程落库为"题目 + 拼接回答"（见 §4），画像流水线零改动。

## 2. 为什么这才是"agent"

v1 里模型只决定"下一道问哪题、要不要追问"，题目、顺序空间、评分全是预设的，本质是带自由度的脚本。v2 里模型拥有真实面试官的三样东西：目标（简报）、记忆（scratchpad）、专业知识（技能包 + 简历 + 查阅工具），每回合基于它们做决策；代码拥有预算、不变量、落库与公平性。这与项目一贯的"模型提案、程序裁决"一致，只是把"提案"的范围从"选题"扩大到"整场面试怎么开"。对求职叙事而言，这正是 Agent Harness、context management、tool use、budget 的完整实践。

## 3. 公平性怎么守

v1 的公平来自"每题评分表预生成"。v2 的题目是临场生成的，公平改由**领域评分表**承担：同一份 JD 生成同一套领域与锚点，评分只对照它，不对照具体问了什么。这与结构化面试（BEI / 胜任力面试）的做法一致，比逐题 rubric 更接近真实评价。代码侧的硬门：评分表在开场前冻结；评分 agent 不得改写评分表；证据句逐字来自回答；面试官的追问与提示不得含评分表原文。

## 4. 数据与接口

**数据**
- `InterviewBrief`（新，JSON 存在会话上）：领域、评分表、假设、切入问题、时长。
- `MockInterviewMessage`（新）：role、kind、content、threadId、turnIndex、toolName、voiceMetricsJson。
- `InterviewThread`（新）：sessionId、areaId、openedAtTurn、closedAtTurn、status（active/closed/skipped）、noteJson。
- **兼容层**：线程关闭时写一条 `InterviewQuestion`（question = 切入问题 + 追问摘要，answer = 该线程候选人回答拼接，category 按领域）和对应的评分记录（rubric = 领域评分表）。复盘、历史、画像、投递关联全部不改。
- `MockInterviewSession`：新增 `briefJson`、`durationMinutes`、`memoryJson`；`questionCount / currentQuestionIndex` 降为展示用推导值。

**接口**
- `POST /api/interviews/mock`：创建会话并后台备课（复用现在的后台生成与状态机，`generating → in_progress`）。
- `POST /api/interviews/mock/[id]/turn`：流式回合；请求带客户端 messageId 幂等；流结束后一个事务写消息、线程、记忆、effects。
- `POST /api/interviews/mock/[id]/complete`：复用，评分改为按领域。
- 体验版：`/api/trial/brief`、`/api/trial/turn` 无状态版本，请求体带简报、记忆与最近消息；纯函数核心共用，浏览器存储。

**运行时**：`run-agent.ts` 增加 `streamAgent`，与 `runAgent` 共用防注入基座、超时、错误分类与 trace 落点；工具执行只回答"代码是否允许"，状态变更由 reducer 在流结束后统一应用。

**前端**：`useChat` 接流的聊天房间；右侧是领域覆盖进度与时间条；工作记忆面试中不展示，报告页展示。

## 5. 复用与删除

| 复用 | 删除 |
|---|---|
| 岗位蓝图 agent 与降级链（领域来源） | 出题 agent 的配额、去重、两轮贪心（题目不再预生成） |
| 技能包目录、选择器、`load_skill` | 分步房间 `mock-interview-room.tsx` |
| 证据逐字检查、注入防护、trace | `answering.ts` 的题号推进；`follow-up-agent.ts`、`follow-up-policy.ts` |
| 逐题评分 agent（改为按领域）、总结 agent | `/answer`、`/api/trial/follow-up` 接口 |
| 转写与语音指标 | 体验版逐题状态机 |
| 画像流水线（经兼容层） | |

现有出题评测的判分器大半失效（它们判的是"题目集合"），备课阶段需要新的判分器（领域覆盖、评分表锚点数、假设引用真实）；面试阶段的判分器见 §7。评测扩展暂停，但 trace 照常记录，判分器后补。

## 6. 分期

| 期 | 内容 | 预估 |
|---|---|---|
| P1 | 简报生成（领域 + 评分表 + 假设 + 切入问题）；纯函数核心（状态、记忆、预算、reducer、分段、fallback）；`streamAgent`；`/turn`；聊天房间（文字）；按领域评分与总结；兼容层落库；旧会话只读回放；删除清单 | 4–5 天 |
| P2 | 语音回合；体验版同构；候选人插话的完整处理；报告页展示工作记忆 | 2 天 |
| P3 | 按轮次人设（一面/二面/HR）；根据回答质量动态调阶梯上限；简报里的假设跨场沉淀进画像 | 择机 |

### P1 实施记录（2026-09-07，已完成并用真实模型跑通）

真机验证时暴露的四个问题与裁决，都落在代码而不是提示词里：

- **一回合只取一个推进动作。** 推理型模型偶尔在同一回合先 `ask_intro` 再 `open_thread`。取第一个被预算接受的动作，后面的作废；全被拒绝时把最后一个交给 reducer 走 fallback。
- **面试官的话只取最后一步。** 模型在工具调用之后常再单独说一步，并把前一步复述一遍（`stepTexts` 按步保留，`speech` 取最后一步非空文本；前端流式渲染也只显示当前步骤）。
- **一个动作一条消息。** 模型的话几乎总带着问句（多是工具入参问句的改写），再单独落一条"问题"消息就会问两遍。现在 `utterance(speech, question)`：话里有问号就只用话，没有才把工具入参问句接在后面。追问消息因此含回应语，切段时原样进入题目文本，评分不受影响。
- **领域数跟着时长走。** 每个领域至少 5 分钟、最多 5 个，`maxAreasForDuration` 同时写进简报提示词和裁剪逻辑（超出按权重舍弃）；15 分钟只开 2 个领域。

已删除：`answer` 接口、`answering.ts`、`personalization.ts`、旧出题评测（`evals/{assemble,runner,types,generation-graders}`、`scripts/eval*.ts`、`baseline.json`）。冻结的 JD 数据集保留，等简报评测重写时复用。旧的分步出题模块只剩体验版在用，P2 同构后删除。

## 7. 评测（后补，先记下判什么）

- 备课：领域数与配额之和；评分表每级有锚点；假设引用逐字在简历里；切入问题不空洞（技能包坏题模式检测）。
- 面试：每领域至少一线程；线程深度不超上限；救场不超一次；追问/提示不含评分表原文；候选人说跳过确实跳过；连续无动作被强推的次数；回合失败率与降级率。
- 评价：证据句逐字；蜕变测试（改坏回答分数必须降）；重测方差。

## 8. 风险

| 风险 | 对策 |
|---|---|
| 小模型驾驭不了"说话 + 动作 + 记忆更新" | 记忆更新做成结构化小输出；无动作即继续对话；连续无推进强推；解析失败直接问切入问题 |
| 临场题目质量不如预生成 | 切入问题在备课时生成并过检查；追问由阶梯与记忆牵引；技能包坏题模式做逐字检测 |
| 成本：回合数多 | 记忆替代远处原文；每回合 3–5k token；45 分钟约 25 回合，与现在一场评分同量级 |
| 公平性被质疑 | 领域评分表冻结 + 证据逐字 + 评分与提问分离，报告页展示评分表 |
| 流已发出而落库失败 | 流结束再写库；失败则下一回合以库为准重建，前端提示未保存 |

## 9. 待定（默认值）

- 时长选项：15 / 30 / 45 分钟（默认 30）。
- 领域数：3–5，由蓝图能力项聚合（默认 4）。
- 阶梯上限：4 级；救场 1 次；同领域最多 2 个线程。
- 自我介绍：一面默认要，其他轮次可关。
- 工作记忆是否在面试中对用户可见：默认不可见，报告页可见。
