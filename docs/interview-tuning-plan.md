# 面试质量微调：计划

> 基于 [interview-simplify-plan.md](interview-simplify-plan.md) 完成后的现状（面试流程见 [面试前](interview-flow-before.md) / [面试中](interview-flow-during.md) / [面试后](interview-flow-after.md)，评测见 [eval.md](eval.md)）。
> 2026-09-12 第二稿。按"像不像真实面试"排序，评测数字只作验收，不作目标。
> 执行状态：§7 已定（硬门拒一次；追认保留但降频；字数不设硬上限）；第 1–3 步已实现（2026-09-12），回归与真机记录见 §8；第 4 节以后再说。

## 0. 为什么先做这个

用户定的原则：模拟面试的价值在项目追问，八股覆盖率只作门禁。简化之后回合机制已经稳定（替换率 0、卡住后换题 2 回合、不再闪烁），剩下的差距是"问什么、怎么说"，三处最不像真实面试：

| 现象 | 数据 | 真实面试官会怎么做 |
|---|---|---|
| 答完切入问题就换话题 | simplify-4 的 45 条线程里 28 条一层没追（trial-3 是 17 条里 3 条） | 听完项目介绍一定追"这块是你做的还是别人做的""为什么选这个方案" |
| 简历上的说法从不核实 | 简历假设被追率三次运行都是 0 | 看到"响应时间下降 40%"直接问怎么量的、基线是什么 |
| 每回合说一大段 | 每条面试官消息 100–200 字，"追认 + 纠偏 + 问题"三段式 | 多数时候一句过渡就问下一个问题，偶尔才点评 |

三项都不加动作、不改回合机制，只改代码在什么时候拒、提示词里放什么与要求说多少。

## 1. 最少追一层

### 现状
两步回合里"决定"这一步偏好 close_thread + open_thread。切入问题是备课写的、谁都能提前准备，追问才是面试；一层不追，弱项暴露不出来，评分也分不开。

### 改动
- **硬门（代码，与锚点硬门同一套重试机制）**：线程 depth 小于领域目标深度、且候选人对上一问有实质回答（kind=answer，不是卡住 / 跳过）时，close_thread 第一次被拒绝："这段还没追问过，先顺着候选人的回答追一层再关"；第二次照常接受。到深度上限或候选人卡住时不拒。
- 决定提示词里把"问够了就 close_thread"改成"每个领域至少追问到目标深度，除非候选人明显答不上"。

### 验收
线程 0 层的比例 ≤ 20%；追问贴合率、锚点命中率不降；每场回合数上升在预算内（安全上限不触发）。

## 2. 简历假设进线程

### 现状
备课为简历生成 ≤ 6 条假设（text、evidence 逐字、areaId 可空）。面试中它们只出现在系统提示词"工作记忆 → 尚未验证的简历假设"一节，与当前线程无关；模型通过 note 改状态，没人要求它改。汇总时 open 的假设由汇总模型补判，所以报告里偶尔有结论，面试里从没追过。

### 改动
- **备课**（brief-v9）：project 领域必须至少挂一条假设（areaId 指向它），text 写成"面试里问什么才能验证"（例如"简历称响应时间下降 40%：问基线怎么量、样本多大"）。project 领域没有假设时，代码从简历里该项目的描述取带数字或成果词的一句生成一条兜底假设（evidence 逐字），保证每个项目线程都有东西可对质。
- **面试中**：开线程时把挂在该领域上的 open 假设写进"当前线程"一节，决定与说话两步都带：
  > 这段要验证的简历假设：[H1] 简历写「响应时间下降 40%」——问基线怎么量、样本多大。验证到了就在 note 里把它标成 confirmed / refuted。
- **硬门（代码）**：project 线程还有 open 假设、且追问层数没到上限时，close_thread 第一次被拒绝（"还有假设 H1 没验证，先追一层"），第二次照常接受。与第 1 步的硬门合并成一次拒绝：拒绝理由里同时列出"没追问过 / 还有假设没验证"。
- **收尾**：close_thread 时该领域仍 open 的假设，代码在线程 note 后追加"这段没验证到 H1"（不改状态，留给汇总）。

### 验收
简历假设覆盖率 ≥ 0.75、被追率 > 0；对照组误报率仍为 0（答得好的候选人假设应被 confirmed，不能被 refuted）。真机：项目线程里面试官问到简历上的数字或成果。

## 3. 说话收短

### 现状
说话提示词要求"先回应（追认 / 纠偏 / 对质三选一）再提问"，每回合都是三段式，100–200 字。真实面试官大多只说一句过渡就问下一个问题，点评是偶尔的。

### 改动
- 说话规则改成：**默认直接问**——一句话承接候选人刚说的（可以没有），然后问题；**纠偏与对质才展开**——候选人说错了、或与简历矛盾时，先一两句指出来再问；**追认降频**——答到关键处可以用半句点一下，不必每回合，不展开夸。像当面说话那样短，不设字数硬上限。
- 开场白、提示、收尾同样只说该说的（提示 ≤ 80 字已有）。
- 代码不截断（截断会断句），模型输出预算放宽到不会截断；trace 页标出超长的话，评测记"面试官每条消息字数"作基线。

### 验收
面试官每条消息字数中位数明显低于现在（现在 100–200 字）；纠偏率不降（错句仍被当场指出）；真机读一场对话，像面试不像点评。

## 4. 顺手做 / 以后再说

- **技能包切片进线程**（原第 2 步）：开线程时代码把领域对应的技能包主题切片（≤ 500 字）放进当前线程一节，删掉回合里的 load_skill。不是真实面试问题，是让追问更尖；省一次工具调用，第 1–3 步跑通后顺手做。
- **技能包内容补缺**：前端的浏览器存储 / HTTP 缓存 / 路由权限，运维的监控告警 / MySQL 高可用，后端的 Spring 核心 / 网络协议。八股覆盖面按原则只是门禁，以后再说。
- **评测修正**（不扩框架）：人设模拟器把错句说了 4–5 遍（persona-2），错句落进四五条线程，"强弱分得开"测不出东西。改成错句说过一次后提示词里要求不再复述；运行器已有 saidClaim 判断，只是没喂回模拟器。与第 1 步一起做，否则第 1 步的验收看不清。

## 5. 实施顺序与验收

| 步 | 内容 | 验收 | 预估 |
|---|---|---|---|
| 1 | 最少追一层（§1）+ 评测修正（§4） | 单测：硬门拒一次、卡住不拒；`interviewer --k 2` 四用例：0 层线程 ≤ 20%，强弱分开率 ≥ 0.75 | 0.5 天 |
| 2 | 简历假设进线程（§2）+ brief-v9 | 单测：project 领域兜底假设、硬门合并；真机一场看对质；回归看被追率 > 0 | 0.5 天 |
| 3 | 说话收短（§3）+ interviewer-v6 | 真机读一场对话；回归看字数中位数与纠偏率 | 0.5 天 |

第 1 步单独跑一次面试官回归（它是最大的变量）；第 2、3 步合并跑一次。每步各自提交，推送前问你。

## 6. 何时跑回归、花多少

用户定的规则（2026-09-12）：**评测不是质量门禁，改动质量靠实际使用的感受。** 评测对这个项目唯一的意义是简历上的量化结果，所以默认不跑；只在能产出"改造前 vs 改造后"对照数字时跑一次完整回归（改造前的数字已有：eval.md §6 基线、simplify 计划 §9.5），之后不再跑，跑之前先问。日常改动只跑单测 + 真机一场（约 10 回合，10 万 token 内），观察记进执行记录。

| 改动 | 单测 | 真机一场 | 面试官回归 `interviewer --k 2`（8 场） | 覆盖率门禁 `coverage --k 4`（40 份简报） |
|---|---|---|---|---|
| 回合逻辑、面试官提示词、reducer | 必跑 | 跑 | 只为一次前后对照 | 不跑 |
| 备课提示词、装箱、技能包内容 | 必跑 | 跑（看简报） | 不跑 | 只为一次前后对照 |
| 房间 / 报告 / 文档 / 体验版接口形状 | 必跑 | 跑 | 不跑 | 不跑 |

一次面试官回归的用量（simplify-3 实测，含 8 场面试、逐段评分与示范、汇总、模拟器与裁判）：主模型 gpt-5.4-mini 约 136 万输入 + 10 万输出 token，辅模型 deepseek-chat 约 14 万输入 + 1.3 万输出；大头是决定这一步（62 万）、示范回答（23 万）、备课（23 万）。一次覆盖率门禁只跑备课，40 份简报约 100 万 token。按你账户里两个模型的单价乘一下就是钱；量级是"每次几美元以内"，不是每改一行都跑的东西，所以上表把 UI 与文档改动排除在外，先跑单测、真机看一场，再决定要不要跑回归。

## 7. 已定（2026-09-12）

1. **硬门拒一次**：同一回合里第一次 close_thread 被拒（工具只回原因、不改状态，模型重选动作），第二次放行，给"这人确实答不出"留出口。
2. **追认保留但降频**：默认直接问，答到关键处可以用半句点一下，不必每回合。
3. **字数不设硬上限**：提示词只要求短，输出预算放宽到不会截断，超长的在 trace 页标出。

## 8. 执行记录（2026-09-12）

### 8.1 代码

- **第 1 步**：`budget.probeBeforeClose` 返回拒绝理由（没追到目标深度、或挂在该领域上的简历假设还没验证，且还能追问）；`turn-agent.buildDecideTools` 里 close_thread 第一次命中就拒、第二次放行（`closeRefused`）。决定提示词改为"每个领域至少追问到目标深度再关，只有候选人明显答不上时才提前关"。
- **第 2 步**（brief-v9）：备课提示词要求每个 project 领域至少一条假设、text 写成"问什么才能验证"；`brief.fallbackHypothesis` 在简历里该项目的段落（项目名到下一个项目名之间）找带单位的数字或成果动词的一句逐字作 evidence，只有标题行（带日期）或找不到就不补；模型没挂领域的假设按证据句所在的项目段落挂上（`attach`）。面试中"当前线程"一节带该领域仍 open 的假设（决定与说话都带）；面试官自己关掉仍有 open 假设的线程时 note 后追加"（没验证到 H1）"。
- **第 3 步**（interviewer-v6）：说话规则改为默认直接问、说错或与简历矛盾才展开、答到关键处可用半句点一下；开场与收尾各一句；说话预算 600 → 1200 token 只防跑飞，代码不截断；trace 页把超过 150 字的话标"较长"。
- **评测修正**：模拟器错句说过一次后提示词改为"不要再复述"；新增指标"一层没追的线程占比"（≤ 0.2）与"面试官每条消息字数 p50"。
- 单测：硬门拒一次 / 到目标深度不拒 / 有 open 假设先拒 / 关线程记"没验证到"；兜底假设取成果句、跳过标题行、模型假设按段落挂领域。`npm test` 422 通过，tsc、eslint 全绿。

### 8.2 真机（字节财经 AI 应用实习 JD，快速节奏，本地 3000）

- 开场只剩一句："你好，请用一两分钟介绍一下和这个岗位相关的经历。"
- 切入项目后连续两层追问而不是换领域：第一问"哪些是你自己从零写的、哪些是改造或集成的"，候选人答完后追"分层记忆具体写了哪些层、工具协议定义了哪些字段"。
- 第三回合面试官抓住"每次开场全量注入"与简历里"动态检索和 pinned memory"的矛盾当面问。每条话两三句。
- 暴露的两个问题当场修掉：兜底假设取到了项目标题行（年份被当成数字）；模型自己写的假设没挂领域，开线程时带不上。

### 8.3 回归

`tuning-1`（第一次跑）赶上服务商故障：19:48–20:00（UTC）gpt-5.4-mini 的所有 agent 成批 provider_error（决定 23 次、说话 27 次、评分 14 次、备课 2 次），deepseek 的裁判正常。后三场基本是兜底在跑（两场用了兜底简报、没有假设；19 回合"模型回合失败"由代码关线程），数字不能用。有效的信号只有：追问 34 次（simplify-4 是 20 次），面试官每条消息字数 p50 83（之前 100–200），每回合 token 13.8k → 10.4k。

`tuning-2`（重跑）：整场全部失败——探活发现 OpenAI 账户额度用完（429 `insufficient_quota` / `credit_balance_exhausted`），tuning-1 后半段的"服务商故障"其实就是额度耗尽的开始。8 场全靠兜底简报与固定措辞跑完，两份运行产物都已删除，不留在 `eval/runs/` 里误导比较。按 §6 的新规则，第 1–3 步不再重跑回归；充值后真机一场确认即可。要做的唯一一次评测是"改造前 vs 改造后"对照（`interviewer --k 2 --cases hints,persona-1,persona-2,control-1 --label after-tuning`，对照 trial-3 / simplify-4），时机由用户定，验收口径不变：0 层线程 ≤ 0.2、简历假设覆盖率 ≥ 0.75 且被追率 > 0、面试官每条消息字数 p50 明显低于 100、强弱分开率 ≥ 0.75。

顺带暴露的一个产品问题（本轮不改，记在这里）：模型因额度或故障不可用时，回合走"模型回合失败 → 代码关线程开下一领域"的兜底，候选人看到的是一连串固定措辞的切入问题，面试还在往下走。更合适的是把配额 / 鉴权类错误当成不可恢复的失败直接报给房间（"模型不可用，请检查设置"），兜底只留给偶发超时。
