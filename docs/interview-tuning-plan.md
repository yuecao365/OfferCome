# 面试质量微调：计划

> 基于 [interview-simplify-plan.md](interview-simplify-plan.md) 完成后的现状（面试流程见 [面试前](interview-flow-before.md) / [面试中](interview-flow-during.md) / [面试后](interview-flow-after.md)，评测见 [eval.md](eval.md)）。
> 2026-09-12 第一稿。目标不是加功能，是把评测里几个数字做对：线程一层都没追的比例（简化后新出现）、简历假设被追率 0、技能包加载率 0.75、备课话题缺口。
> 执行状态：待放行。

## 0. 为什么先做这个

用户定的原则：模拟面试的价值在项目追问，八股覆盖率只作门禁。简化之后回合机制已经稳定（替换率 0、卡住后换题 2 回合、不再闪烁），剩下的差距全在"问什么"：

| 数字 | fix-1 | trial-3 | simplify-3 | 含义 |
|---|---|---|---|---|
| 线程一层都没追的比例 | 3/17 | 20/32 | 28/45（simplify-4） | 两步回合后面试官答完切入就换领域 |
| 简历假设被追率 | 0.00 | 0.00 | 0.00 | 备课写了"要验证的简历假设"，面试官一次都没验证到非 open |
| 简历假设覆盖率 | 0.67 | 0.67 | 0.25 | 备课为"说不出细节的成果"生成假设的场次比例，广度优先后反而降了 |
| 技能包加载率 | 0.75 | 1.00 | 0.75 | 决定这一步有可用动作就停，模型常常不查包就追问 |
| 备课话题覆盖（深入节奏） | — | — | 见 eval.md §6.3 | 缺口在技能包内容：前端的浏览器存储 / HTTP 缓存 / 路由权限，运维的监控告警 / MySQL 高可用，后端的 Spring 核心 / 网络协议 |

"对质简历"是用户最想要的体验，而它现在完全靠模型在工作记忆的角落里想起来。三项都不改机制、不加动作，只改提示词里放什么和代码在什么时候放。

## 1. 最少追一层

### 现状
两步回合里"决定"这一步偏好 close_thread + open_thread：simplify-4 的 45 条线程里 28 条一层都没追，候选人答完切入问题就被换领域（trial-3 是 17 条里 3 条）。切入问题是备课写的、谁都能准备，追问才是模拟面试的价值所在；一层不追，弱项暴露不出来，评分也分不开。

### 改动
- **硬门（代码，与锚点硬门同一套重试机制）**：线程 depth 小于领域目标深度、且候选人对上一问有实质回答（kind=answer、非卡住 / 跳过）时，close_thread 第一次被拒绝："这段还没追问过，先顺着候选人的回答追一层再关"；第二次照常接受。到深度上限或候选人卡住时不拒。
- 决定提示词里把"问够了就 close_thread"改成"每个领域至少追问到目标深度，除非候选人明显答不上"。

### 验收
线程追问层数分布：0 层的比例 ≤ 20%；追问贴合率、锚点命中率不降；每场回合数上升在预算内（安全上限不触发）。

## 2. 简历假设进线程

### 现状
备课为简历生成 ≤ 6 条假设（`hypotheses[]`：text、evidence 逐字、areaId 可空）。面试中它们只出现在系统提示词"工作记忆 → 尚未验证的简历假设"一节，与当前线程无关；模型通过 note 工具改状态，没人要求它改。汇总时 open 的假设由汇总模型按各段判断补状态，所以报告里偶尔有结论，面试里从没追过。

### 改动
- **备课**（brief-v9）：project 领域必须至少挂一条假设（areaId 指向它），假设的 text 写成"面试里问什么才能验证"（例如"简历称响应时间下降 40%：问基线怎么量、样本多大"）；technical / behavioral 领域的假设可选。代码校验：假设的 areaId 不在简报里的置空（已有）；project 领域没有假设时，代码从简历里该项目的描述取带数字或成果词的一句生成一条兜底假设（evidence 逐字），保证每个项目线程都有东西可对质。
- **面试中**：开线程时，把挂在该领域上的 open 假设写进"当前线程"一节，决定与说话两步都带：
  > 这段要验证的简历假设：[H1] 简历写「响应时间下降 40%」——问基线怎么量、样本多大。验证到了就在 note 里把它标成 confirmed / refuted。
- **硬门（代码）**：project 线程还有 open 假设、且追问层数没到上限时，close_thread 第一次会被拒绝（"还有假设 H1 没验证，先追一层"），与锚点硬门同一套重试机制；第二次照常接受。到深度上限时不拒。
- **收尾**：close_thread 时该领域仍 open 的假设，代码记 note"这段没验证到 H1"进线程 note 之后（不改状态，留给汇总）。

### 删除
无。汇总模型对 open 假设的补判保留（面试里没碰到的假设仍需要一句结论）。

### 验收
`interviewer --k 2 --cases persona-1,persona-2,persona-3,control-1`：简历假设覆盖率 ≥ 0.75（每场至少一个项目领域，就至少一条假设）、被追率 > 0；对照组误报率仍为 0（答得好的候选人假设应被 confirmed，不能被 refuted）。

## 3. 技能包不靠模型查

### 现状
回合的决定这一步带 load_skill 工具与索引，模型自行决定查不查；有可用动作就停，两场里一次没查。查了也是整包（后端包 2 万字），一回合最多两次。

### 改动
- 开线程时代码把领域对应的技能包**主题切片**放进"当前线程"一节（决定与说话都带）：baseline 领域按 `baseline.topic` 精确取 `### 主题` 一节（阶梯、好题、危险信号、期望信号，约 300–500 字）；JD 来源的 technical 领域按领域名与主题标题的关键词重合取最匹配的一节，没有重合就不放；project / behavioral 领域取 project-deep-dive / behavioral 包里"项目结合钩子"一节。
- 切片由代码在备课时算好存进简报领域（`area.reference: { skill, topic, text } | null`），面试中不再读包文件；体验版随简报一起带到浏览器。
- 决定这一步删掉 load_skill 与索引；决策记录的 `skillsLoaded` 改为"本线程有无参考资料"（0 / 1），评测指标"技能包加载率"改为"线程带资料率"，期望 ≥ 0.9。

### 删除
`turn-agent.ts` 里的 `createSkillTools` 调用与提示词里的索引段；`MAX_DECIDE_STEPS` 4 → 3（note + 动作 + 被拒后换一次）。备课的 load_skill 不动。

### 验收
线程带资料率 ≥ 0.9；追问贴合率、锚点命中率在噪声内；每回合 token 不高于现在（切片 ≤ 500 字，换掉的是索引 + 偶发的整包加载）。

## 4. 技能包内容补缺

### 现状
eval.md §6.3 / §7.2 的结论：备课提示词对话题覆盖率无作用，缺口是技能包里没有这些主题。各岗 `missed` 列表：前端——浏览器存储、HTTP 缓存、路由权限；运维——监控告警、MySQL 高可用；后端——Spring 核心、网络协议。

### 改动
按现有格式（`### 主题`：阶梯 / 好题 / 危险信号 / 期望信号）给 frontend、infra、backend / backend-java 各补 2–3 个主题，每个主题一段，不改代码。补完跑 `coverage --k 4` 看五岗加权覆盖率是否一起抬，并把新的 `missed` 列表记回 eval.md。

### 验收
`coverage --k 4`：被补的三个岗位覆盖率上升超出各自噪声（前端 0.09、运维 0.08、后端 0.13，见 eval.md §6.3），其余两岗不降。

## 5. 评测修正（不扩框架，只修一处失真）

人设模拟器的提示词要求"只要问题沾到话题就把错句放进回答"，persona-2 两场各说了 4–5 遍，错句落进四五条线程，"弱项线程 vs 其他线程"的分开率因此测不出东西。改成：错句说过一次之后，提示词里换成"这句你已经说过，不要再重复，被追问时可以解释但不要复述原句"；运行器已有 saidClaim 判断，只是没把它喂回模拟器。同时把"强弱分得开"的弱项线程定义固定为错句**第一次**出现的线程（现在已是）。

## 6. 实施顺序与验收

| 步 | 内容 | 验收 | 预估 |
|---|---|---|---|
| 1 | 最少追一层（§1）+ 评测修正（§5） | 单测：硬门拒一次、卡住不拒；`interviewer --k 2` 四用例：0 层线程 ≤ 20%，强弱分开率回到 trial-3 的水平（≥ 0.75） | 0.5 天 |
| 2 | 简历假设进线程（§2）+ brief-v9 / interviewer-v6 | 单测：project 领域兜底假设、硬门拒一次；同一次回归看被追率 > 0 | 0.5 天 |
| 3 | 技能包切片进线程（§3） | 单测：切片按主题精确取、关键词匹配、无匹配为空；同一次回归看线程带资料率 | 0.5 天 |
| 4 | 技能包内容补缺（§4） | `coverage --k 4` 三岗上升 | 0.5 天（写内容） |

第 1 步单独跑一次面试官回归（它是最大的变量，要单独看）；第 2、3 步合并跑一次；第 4 步只动内容，跑覆盖率门禁。每步各自提交，推送前问你。

## 7. 何时跑回归、花多少

| 改动 | 单测 | 面试官回归 `interviewer --k 2`（4 用例 8 场） | 覆盖率门禁 `coverage --k 4`（5 岗 40 份简报） |
|---|---|---|---|
| 回合逻辑、面试官提示词、reducer | 必跑 | 跑 | 不跑 |
| 备课提示词、装箱、技能包内容 | 必跑 | 不跑 | 跑 |
| 房间 / 报告 / 文档 / 体验版接口形状 | 必跑 | 不跑 | 不跑 |

一次面试官回归的用量（simplify-3 实测，含 8 场面试、逐段评分与示范、汇总、模拟器与裁判）：主模型 gpt-5.4-mini 约 136 万输入 + 10 万输出 token，辅模型 deepseek-chat 约 14 万输入 + 1.3 万输出；大头是决定这一步（62 万）、示范回答（23 万）、备课（23 万）。一次覆盖率门禁只跑备课，40 份简报约 100 万 token。按你账户里两个模型的单价乘一下就是钱；量级是"每次几美元以内"，不是每改一行都跑的东西，所以上表把 UI 与文档改动排除在外，先跑单测、真机看一场，再决定要不要跑回归。
