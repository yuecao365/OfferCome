## 一、调研参考

| 参考对象 | 学什么 |
| --- | --- |
| [Linear](https://linear.app)（高级感标杆） | 克制的设计语言：单一强调色只用于品牌/焦点/主 CTA；四级表面梯度承担层次；用 1px 边框 + inset 高光代替大投影；标题负字距；active 态缩放 ~0.97 的触感反馈 |
| [Midday](https://github.com/midday-ai/midday)（开源，~14k star） | shadcn 生态公认最精致的数据密集型工作台，指标卡、表格、空状态可直接翻源码对照 |
| Huntr / Teal（同类求职追踪产品） | Huntr 的管道可视化直观；Teal 的教训是功能堆太密显得拥挤——我们不加密度，只加层次 |
| Google Interview Warmup / Yoodli | 面试训练报告的可视化呈现（评分、语速等以图形而非纯文字给出），对模拟面试报告页有参考价值 |
| SaaS onboarding 通行做法 | 数据驱动的 checklist + 空状态引导单一动作 + 渐进披露；不做多步弹窗式导览 |

## 二、现状评估（走查全部页面后）

**已经做得好的**：语义化 token + 完整暗色主题；button/card/badge 等组件统一；a11y 基础扎实（focus ring、skip link、reduced-motion）；页面/弹窗进入动画已有体系。基建是健康的，不需要引入组件库或重写。

**差距**：

1. **加载体验**：各页 loading 是一行"正在加载"文字，不是与布局一致的骨架屏；数据概览首屏在 dev 下停留加载态 30s+（另外 DOM 中发现残留多个 `<main>`，疑似加载页未被正确替换，属体验 bug，需排查）。
2. **视觉层次单薄**：卡片只有一档极浅阴影，surface 梯度没被用出层次；指标数字没有展示级字号和 tabular-nums，排版缺乏节奏。
3. **没有新手引导**：空数据库用户进来看到空表格；「配 Key → 传简历 → 录投递 → 首次模拟」的路径全靠自己摸。
4. **微交互弱**：hover/active 反馈浅，操作成功/失败反馈方式不统一。
5. **图表默认感**：recharts 默认网格线/tooltip 样式明显，和整体绿色调不融合。

## 三、修改计划（四批）

### 批次 1：设计基建（token 升级，影响面最小，先行）

- `globals.css`：明确四级表面梯度及 hover 态；阴影体系改为 1px 边框 + inset 高光 + 两档柔和投影；新增动效 token（统一 duration / easing）。
- 排版：新增 display 级字号（指标数字、页面标题用），数字统一 `tabular-nums`；标题负字距已有，微调节奏。
- `button.tsx` 等少量组件：active 态加 `scale-[0.98]` 类触感反馈（保留 reduced-motion 豁免）。
- 只动 token 和 2~3 个基础组件，全站自动受益。

### 批次 2：加载与过渡体验

- 各主要页面 `loading.tsx` 换成与真实布局一致的骨架屏（`skeleton.tsx` 已存在，铺开用）。
- 图表/画像画布懒加载占位统一。
- 顺带排查两个体验 bug：数据概览首屏为何长时间挂起；DOM 残留多个 `<main>` 的原因。

### 批次 3：用户引导（贴合"少操作"北极星）

- 数据概览顶部加**数据驱动的开始清单卡**：未配模型 Key / 无简历 / 无投递 / 未做过模拟时逐项显示，各项直链对应页面；条件满足自动消失，不需要用户手动关闭。
- 空状态升级：每个空页面一句话说明 + 单一主行动按钮（`empty-state.tsx` 已存在，补内容和入口）。
- **不做**多步弹窗式 product tour（打扰用户、维护成本高）。

### 批次 4：关键页面质感打磨

- **数据概览**：指标卡排版、趋势图与阶段分布图的配色/网格线/tooltip 融入主题。
- **投递岗位**：卡片内公司/岗位/状态的字重与层次对比、hover 提升。
- **模拟面试房间 + 报告**（核心体验，重点）：对话流节奏、提交反馈、报告页参考 Yoodli 做可视化评分呈现。
- **能力画像**：画布已有质感，微调即可。

## 四、验收方式

每批改完在运行中的页面上实际走查对比（需要浏览器面板可见才能截图），明暗两套主题都验证。
