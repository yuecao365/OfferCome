# 面试流程重构：按真实一面的阶段组织

> **历史文档**：阶段 × 预算的结构已被 [interviewer-agency-plan.md](interviewer-agency-plan.md) 取代。保留作为决策记录。

> 2026-09-13 第一稿。前两轮微调见 [interview-tuning-plan.md](interview-tuning-plan.md)、[interview-pacing-plan.md](interview-pacing-plan.md)。这份文档不再打补丁，回答两个问题：现在的现象为什么反复出现（结构原因），以及流程要改成什么样才在环节、广度、深度、方法、体验上靠近真实一面。

## 0. 现象为什么反复出现：结构原因

现在的面试是一张平面清单：备课产出 4–6 个"领域"，每个领域带目标深度、阶梯、切入问题；面试中每个领域开一条线程，追到目标深度就换下一个；信息量按清单覆盖率算；清单问完就结束。两轮真机暴露的所有问题都能追到这个结构上的五点。

**R1 只有一种方法。** 所有领域用同一套"开题 → 追到目标深度 → 关线程"。真实一面对不同环节用不同方法：项目是深挖（顺着候选人说的往下追，问"你做的哪部分、为什么这么选、怎么量"）；基础题是快问快答（一题最多追一层，答不上就下一题）；场景题是引导式（一个开放问题带两三层引导）。同一方法套在基础题上，就出现"评测体系"对着关键词回答追 4 轮；套在项目上，又因为目标深度固定，成了 5 问一个话题。前两轮的补丁（最少追一层、关键词追一次、verdict、一次一问、上限 3 层）全是在给这一种方法加护栏，护栏之间还互相打架。

**R2 深度在备课时定，不是听完回答定。** 真实面试官没有"这题追 3 层"的计划，只有"这个环节还剩多少时间"和"这个回答值不值得追"。目标深度加 `probeBeforeClose` 硬门把追问变成了配额：模型一边被要求"至少追到目标"，一边被要求"关键词就别追"，只能靠更多规则调和。

**R3 广度被结构排除了。** 一个领域花 depth+1 个回合，20 回合只装得下 4–6 个领域；真实一面 8–12 道基础题的广度在这个结构里不可能出现。领域只有一种粒度，没有"一道快问"这样便宜的单位，所以也没有储备：清单即全部，跳过一个就少一个，问完就结束（上一场两次"提示"后直接收尾就是这个）。

**R4 主题由模型自由选，没有覆盖矩阵、历史和随机性。** 技能包 ai-llm 有 12 个主题，模型对同样的 JD + 简历每次都挑与简历最像的那两个（Agent 工具调用、评估体系），于是技术领域重复项目领域（一场里同一话题问 8–10 次），每场重复上一场（日历改期题连出两场）。这不是提示词不够，是"让模型自由选主题"这个机制的必然结果。

**R5 信息量 = 清单覆盖率。** 系统在清单问完时觉得"够了"，与候选人的表现无关；结束由话题耗尽触发，真实面试由时间触发。

结论：继续在领域清单上加规则，会一直在这五点里打转。要改的是面试的组织单位：从"领域 × 目标深度"改成"阶段 × 方法 × 预算"。

## 1. 目标结构：阶段、方法、预算

真实技术一面的骨架（公开面经一致，见 pacing-plan §0.1）：自我介绍 → 项目深挖 → 基础快问 → 一道场景题 → 收尾。每个阶段有自己的方法、深度上限和提示政策；预算按回合分给阶段，不再分给领域。

| 阶段 | 标准 20 回合 | 方法 | 深度 | 提示 |
| --- | --- | --- | --- | --- |
| 开场 | 1 | 请自我介绍 | – | – |
| 项目深挖 | 8 | 顺着候选人的话追：做了什么、你做的哪部分、为什么这么选、怎么量、出过什么问题；验证简历假设。可以换切入点、换项目 | 自适应，一条线最多 3 层；回答实质就继续，空泛就换切入点 | 每条线 1 次 |
| 基础快问 | 7 | 从题池取题，一题一问，最多追 1 层；答不上或只有关键词直接下一题 | 0–1 | 无（按钮是"不会，下一题"） |
| 场景题 | 3 | 一个来自 JD 的开放场景，引导式追问 | 最多 3 | 1 次 |
| 收尾 | 1 | 一句告别 | – | – |

快速 13 回合：1 + 5 + 4 + 2 + 1。深入 32 回合：1 + 13 + 10 + 7 + 1（场景题两道）。

预算规则：阶段预算是软的——一个阶段提前结束（候选人跳过、崩了），剩余回合顺延给下一阶段；一个阶段超时由代码切到下一阶段（模型在阶段内自由，阶段边界由代码守）。题池比需要的大一倍，快问阶段永远不会没题。面试在总预算用完或所有阶段走完时结束，候选人随时可以结束。

深度规则：没有目标深度，只有阶段上限和"回答值不值得追"。每回合模型对候选人上一条回答给一个判断（实质 / 只有关键词 / 答不上，现在的 verdict 从线程级改成回答级），代码据此决定允许的动作：实质 → 可以追；关键词 → 项目阶段可以换切入点追一次，快问阶段直接下一题；答不上 → 下一题。删除 `probeBeforeClose`、`DEPTH_SLACK`、目标深度、阶梯。

## 2. 备课产出什么

备课不再产出领域清单，产出三样东西：

1. **项目计划**：挑 1–2 个项目（简历项目；自我介绍里点到的优先），每个项目 3–4 条"想验证的点"（来自简历假设：写了数字的成果、只写框架名的经历、时间线空洞），不写切入问题和阶梯。面试官在项目阶段拿着这些点，顺着候选人的话去验。
2. **题池**：代码先抽主题，模型再写题。抽样在代码里：从加载的技能包主题里按岗位能力蓝图加权、排除项目计划已覆盖的主题、排除同岗位最近几场问过的主题、带随机种子，抽 10–14 个主题；模型对每个主题写一道具体问题（一句话一个点，带具体边界条件或小场景）和一个追问方向。随机与历史在代码里，模型只负责把题写好，重复和撞项目就结构性地消失了。
3. **场景题**：从 JD 的系统或职责里挑一个场景，写一道开放题加三级引导（每级一句"下一步往哪引"）。

保留：简历假设、期望信号、评分表。删除：areas 的 depth / ladder / weight 装箱、`minAreas` / `MAX_AREAS`、信息量公式 `I = 0.8E + 0.2H`。

## 3. 面试中怎么走

两步回合（决定 → 裁决 → 说话）、锚点校验、一次一问、错误处理、资料抽屉全部保留；变的是动作围绕阶段而不是领域。

- 线程仍是持久化单位，加 `kind`：project / quick / scenario。项目阶段一条线程是"一个项目的一个切入点"，快问阶段一道题一条线程（深度 0–1），场景题一条线程。评分、复盘、画像照旧按线程 → InterviewQuestion 走，不用改（快问题多了之后评分调用可以合并成一次，见 §5）。
- 动作还是 open_thread / probe / close_thread / close_interview，但 `allowedActions` 按阶段算：项目阶段 open_thread 只能开项目切入点，快问阶段 open_thread 只能从题池取题（areaId 换成 poolId），场景阶段只能开场景。阶段切换由代码在预算用完或模型 close_phase 时执行，并让模型说一句过渡（"项目聊到这，问几个基础的"）。
- 候选人插话：跳过 → 本阶段下一题；"不会" → 项目 / 场景阶段给一次提示，快问阶段直接下一题；再说一遍、结束、否认简历不变。
- 工作记忆不变；简历假设挂在项目计划上。

## 4. 体验

- 房间顶栏显示阶段（项目 → 基础 → 场景），候选人知道自己在哪个环节、还剩多少，像真实面试里能感觉到"面试官开始问基础了"。
- 按钮按阶段变：项目 / 场景阶段"给点提示"（一次，用完变灰），快问阶段"不会，下一题"。不再出现"点两次提示就结束"。
- 结束由预算触发，模型说结束语；报告按阶段分节：项目（验证了哪些假设）、基础（答对几道、失守在哪些主题）、场景（引导到第几层）。

## 5. 与现有代码的关系

改：
- `brief.ts` / `brief-agent.ts`：简报结构改成 §2 的三样，schema 与装箱逻辑重写（最大的一块）。brief-v11。
- 新增 `topic-sampling.ts`（技能包主题抽样：加权、排除、随机、历史），历史来自 `buildMockInterviewContext` 已有的同岗位最近题目查询。
- `budget.ts`：阶段预算与阶段内上限，替换 `probeLimit` / `probeBeforeClose` / `coverageComplete` / `canClose` 的清单逻辑。
- `evidence.ts`：删信息量公式，改成阶段进度（各阶段用了几回合、项目假设验证数、快问答对数）。
- `prompt.ts`：按阶段写指令；interviewer-v8。
- `reducer.ts` / `turn-agent.ts`：线程 kind、阶段切换、按阶段的 allowedActions、回答级 verdict。
- 房间与 trace：阶段栏、按钮、trace 的阶段列。报告：按阶段分节。
- 评分：快问线程合并成一次评分调用（一道题一个 InterviewQuestion 不变，只是一次模型调用评多道）。
- 评测指标：领域口径的指标（shallowThreads、hypothesisCoverage）改成阶段口径；评测只为简历对照，指标少而准即可。

删：`DEPTH_SLACK`、`MAX_AREA_DEPTH`、`MAX_AREAS` / `minAreas`、`probeBeforeClose`、领域阶梯、`evidenceTargetForPace`、线程级 verdict（被回答级替代）。

不动：两步回合、锚点校验、一次一问、错误分类与房间重试、资料抽屉、意图识别、体验版同构（View + 注入的结构不变，简报形状变了两边一起变）。

4. 文档原地更新（interview-flow-during.md 到 v8），旧计划文档标记已被本文替代。
