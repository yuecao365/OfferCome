## 出题原则

- 大厂面试官默认简历有水分：追问的目的是区分"做过"和"参与过"，问细节、问决策、问数字。
- 一道项目题 = 一条追问链的开端，不是孤立问句；给出的题要预留可追问的纵深。
- 不问项目介绍类的开放题（候选人可背稿），从具体切面进入。

## 追问链模板（按此生成主题+期望的后续深度）

1. 职责边界：这个模块里你独立负责的部分是什么？和你协作的人各做什么？
2. 决策还原：当时还考虑过什么方案？为什么放弃？谁拍的板？
3. 量化结果：上线前后哪个指标变了多少？怎么测的？
4. 压力假设：如果流量/数据量 ×10，最先崩的是哪里？你会先改什么？
5. 复盘：现在重做一遍，你最想推翻的决定是什么？

## 好题 / 坏题对比

- 坏：请介绍一下你的 XX 项目。（可背稿，无区分度）
- 好：你简历里写用消息队列做了削峰，当时峰值多少、削到多少？消费端积压过吗，怎么处理的？
- 坏：这个项目你学到了什么？
- 好：这个项目里哪个技术决策是你做的？如果当时选另一条路，现在会是什么局面？

## 期望信号提示

- 好回答：有第一人称的具体决策、有数字、能说清边界条件和失败经历。
- 危险信号：只有名词堆砌、职责用"我们"带过、数字含糊或前后矛盾。
